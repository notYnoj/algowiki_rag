<tbc>where for \(\epsilon=1/\text{polylog}(n)\) matrix **P**_<sup>j</sup>_ is \(\widetilde{O}(1)\times n\) dimensional so takes only \(\widetilde{O}(n)\) space. We can query for edge _e_=(_a,b_) the value

\(\sigma((\mathbf{W}^{(j-1)})^{1/2-1/p}\mathbf{V}^{-1/2}\mathbf{A})_e\approx\|\mathbf{P}^{(j)}\mathbf{A}^\top\mathbf{V}^{-1/2}(\mathbf{W}^{(j-1)})^{1/2-1/p}\chi_e\|_2\)<br>
\(=\|\mathbf{P}^{(j)}(\chi_b-\chi_a)\|_2^2\cdot v_e^{-1}(w_e^{(j-1)})^{1-2/p}.\)<br>
\(w_e^{(j)}=((w_e^{(j-1)})^{2/p-1}(\|\mathbf{P}^{(j-1)}(\chi_b-\chi_a)\|_2^2\cdot v_e^{-1}(w_e^{(j-1)})^{1-2/p}+n/m))^{p/2}.\) (3)

Note that in addition to the \(\widetilde{O}(n)\) space for **P**<sup>(1)</sup>_,...,_**P**<sup>(_k_)</sup>, here we need _v<sub>e</sub>_ to compute \(w_e^{(k)}\). We have access to that value since \(v_e=1/x_e^2-1/(u_e-x_e)^2\) and we already established that we can query _x<sub>e</sub>_ when edge _e_ and its capacity _u<sub>e</sub>_ are given to us. While computation of _x<sub>e</sub>_ requires \(\tau_e\) and computing \(\tau_e\) requires _x<sub>e</sub>_, there is actually no circular dependency here. That’s because, if \(x^t,\tau^t\) are the values computed during iteration number _t_ (i.e., \(x^t=x^{t-1}+\delta_x^t\) where \(\delta_x^t\) uses \(\tau^t\)), then querying \(x_e^t\) requires \(\tau_e^t\), but querying \(\tau_e^t\) needs \(x_e^{t-1}\). So after \(t\le\widetilde{O}(\sqrt{n})\) this loop terminates. This does mean though, that we need to keep track/store all previous values of \(\tau\).

In summary, we need \(\widetilde{O}(n)\) space per iteration to store \(\tau\) while supporting queries to \(\tau_e\), for a total of \(\widetilde{O}(n^{1.5})\) space over \(\widetilde{O}(\sqrt{n})\) iterations.

**Storing the flow** _g_ **(Section 5):** We here give only a very high-level description because details on how _g_ is defined require further details about the interior point method. The exact choice of _g_ is crucial for the \(\widetilde{O}(\sqrt{n})\) iteration count, and storing this flow in low space relies on recent developments in IPM- theory: for the classic Lee-Sidford IPM \[LS14\], it is unclear how to store _g_ in such low space, and our low space representation relies on the recently developed variants \[BLL<sup>+</sup>21\] that are robust against additional approximation errors.

In somewhat simplified terms, _g_ is defined w.r.t. _x_, \(\tau\) and reduced costs \(s:=c-\mathbf{A}\sum_t\delta_y^t\). (Note that for any edge _e_=(_w,z_), we can also compute \(s_e=c_e-\sum_t(\delta_y^t)_z-(\delta_y^t)_w\) since we already store the vertex potentials \(\delta_y^t\in\mathbb{R}^V\) and cost _c<sub>e</sub>_ is given at query time.) Flow _g_ also has the property that if for two edges \(e\neq e'\) we have \((\tau_e,x_e,s_e)=(\tau_{e^\prime},x_{e^\prime},s_{e^\prime})\), then \(g_e=g_{e^\prime}\) are the same. Further, because of recent insights in robust interior point methods, we know the algorithm still works when _g_ is defined w.r.t. approximations \(\overline{x},\overline{s},\overline{\tau}\) that differ from the exact values by some \((1\pm\epsilon)\) approximation for \(\epsilon=1/O(logn)\). Thus we can round each \(\tau_e,x_e,s_e\) to multiples of \(1+\epsilon\), then \(g\in\mathbb{R}^E\) contains only \(\widetilde{O}(1)\) distinct values. We store these distinct values \(\widetilde{g}\in\mathbb{R}^{\widetilde{O}(1)}\) in \(\widetilde{O}(1)\) space.

Then during a query, when receiving edge _e_, we (i) compute \(x_e,s_e,\tau_e\), (ii) round them to the nearest multiple of \((1+\epsilon)\), (iii) access the corresponding \(\widetilde{g}_i\).

This is somewhat simplified, since the construction of _g_ from \(x,s,\tau\) is nontrivial. However, those details require further discussion of how the IPM works, which are given in next subsection. With these details, we can then also explain how to implement the construction of these representations in the semi-streaming model. So far, we only discussed how to represent/store these values, but not how to compute them efficiently. This is outlined in Section 3.3, after giving details about the IPM in Section 3.2.

**Remarks on 2-Party Communication** The blackbox reduction from 2-party communication to streaming simulates the streaming algorithm. To simulate one pass over the input, party A passes over their own edge set, then sends their entire memory to party B who continues the current pass over their half of the edges. This reduction would lead to only a trivial \(\widetilde{O}(n^2)\) communication bound as we have \(\widetilde{O}(\sqrt{n})\) iterations with \(\widetilde{O}(n^{1.5})\) space. However, observe that the \(\widetilde{O}(n^{1.5})\) space usage of our algorithm comes from storing each of \(\delta_x^1,\dots,\delta_x^{\widetilde{O}(\sqrt{n})}\) in \(\widetilde{O}(n)\) space. There is no need to send the entire memory to simulate the streaming algorithm in the 2-party model, because both parties already have the representation of \(\delta_x^1,\dots,\delta_x^{t-1}\) when computing the representation of the new \(\delta_x^t\) together when simulating the streaming algorithm. We will see in Section 3.3 that the streaming algorithm needs only \(\widetilde{O}(n)\) additional space and \(\widetilde{O}(1)\) passes to compute \(\delta_x^t\). This implies \(\widetilde{O}(n)\) communication for each \(\delta_x^t\), i.e., \(\widetilde{O}(n^{1.5})\) communication overall.
