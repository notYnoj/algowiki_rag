However, the retrieval of _R<sub>exact</sub>_ requires exhaustive search over the entire dataset, which becomes computationally expensive and incurs high search latency [21]. To address this, DVQ in practice retrieves _k_ approximate nearest results _R<sub>DVQ</sub>_, achieving a trade- off between retrieval accuracy and search efficiency [21, 61]. To quantify the quality of the approximate results _R<sub>DVQ</sub>_, recall [26, 51] is commonly used, defined as \(Recall@k=\frac{|R_{DVQ}\cap R_{exact}|}{k}\) , where _R<sub>exact</sub>_ is the ground-truth set of the _k_ closest objects to _q_. The goal of DVQ is to maximize recall while retrieving results efficiently.

## 2.2 Pareto-Frontier-Based Index Construction

Due to diverse query \(\alpha\) in DVQ, Pareto-frontier-based indices select the Pareto frontiers of each node as its out-neighbors, which can nearly cover the approximate nearest neighbors for all possible \(\alpha\).

**Pareto Frontier** [29]. The construction of Pareto-frontier-based indices can be viewed as finding the Pareto frontier for each node. Given a node \(v\in V\) for which we aim to find its neighbors, each candidate node \(p\in V\backslash\{v\}\) induces a distance pair relative to _v_, \((\delta_x(v,p),\delta_y(v,p))\). For any \(p,q\in V\backslash\{v\}\), we say that _p dominates q_, denoted by \(p\prec q\), if and only if (1) \(\forall i\in\{x,y\},\delta_i(v,p)\le\delta_i(v,q)\), and (2) \(\exists j\in\{x,y\},\delta_j(v,p)<\delta_j(v,q)\). The Pareto frontier of _v_ is defined as \(PF_v\subseteq V\backslash\{v\}\), where \(\forall p\in PF_v\), \(\nexists q\in V\backslash\{v\},q\prec p\), i.e., the neighbors of _v_ in _PF<sub>v</sub>_ cannot be dominated by any node.

**Multi-layer Pareto Frontiers**. In Pareto-frontier-based indices, only using the Pareto frontier of each node as its out-neighbors leads to an extremely sparse graph index. This is because, in a dataset with millions of objects, the size of the Pareto frontier is typically small (e.g., the average size is 8.26 on CC3M) , while hundreds of candidate nodes are usually required to select as the final out-neighbors. To address this, the multi-layer Pareto frontiers \(\{PF_v^1,\dots,PF_v^l\}\) are selected as the candidate out-neighbors of each node _v_, where _l_ is the number of layers bounded by the candidate pool size _ef<sub>construct</sub>_, as shown in Figure 2b. Neighbors in the first layer correspond to the global Pareto frontier. Each subsequent layer is recursively constructed by removing the current Pareto frontier and extracting a new Pareto frontier from the remaining candidates, referred to as FindPF [7].

**Approximate Pareto Frontier Search**. However, the construction of exact multi-layer Pareto frontiers is computationally expensive, as it requires computing distances to all other nodes in the dataset for each node. Therefore, approximate Pareto frontiers are typically used as candidate neighbors for each node, which are constructed using the Greedy Pareto Frontier Search (GPS) to expand candidate neighbors layer by layer (see Algorithm 1). Specifically, GPS iteratively expands unexplored nodes in the lowest layer of Pareto frontiers containing them until no unexplored nodes remain. Finally, the candidate set C is selected as the approximate Pareto frontier.

**Active Range (AR) Computation**. Since the out-neighbors of each node cover the nearest neighbors under varying query<tbc>

<tbc>preferences, a significant portion of the outgoing edges need not be traversed for a given \(\alpha\) value. To accelerate query processing, we assign preference intervals (i.e., _active ranges_) to each edge, enabling the system to selectively traverse only the edges whose active ranges include the query \(\alpha\). However, computing the active ranges of each edge is difficult [61]. DEG adopts an RNG-inspired pruning strategy similar to those used in single-vector graph indices. Specifically, for each candidate neighbor in C corresponding to an outgoing edge, it evaluates the distance to every other candidate neighbor and computes an interval of the parameter \(\alpha\) over which the edge becomes the longest edge in the corresponding triangle configuration. The active range is then obtained by excluding all such intervals from the complete parameter domain [0,1]. This method requires comparing each neighbor of a node with all retained neighbors to determine its active ranges, resulting in a time complexity of \(O(R\cdot|\mathcal{C}|)\), where _R_ is the maximum out-degree.

**Summary**. Existing Pareto-frontier-based DVQ index construction methods still face performance challenges, as the active range computation introduces substantial computational overhead.

## 2.3 Pareto-Frontier-Based Index Updates

In real-world scenarios, timely updates of indices are essential for search accuracy. Although no specialized DVQ index has yet been proposed to efficiently support dynamic updates, especially for node deletions, existing update techniques for single-vector graph- based indices are already well-established [2, 47, 60, 62]. Next, we review representative update methods in existing single-vector graph-based indices. The insertion procedure can follow the same logic as the construction process. Therefore, we focus our discussion on the deletion case.

Existing repair strategies can be broadly classified into the following two categories: 1) _Reinsertion-Based Repair (RBR)_ methods [2, 30, 60] treat affected nodes as newly inserted nodes and reinsert them to reconstruct their out-neighbors. Although these methods can maintain high index quality, the global search incurs significant computational overhead. 2) _Neighbor-Reconnection- Based Repair (NRBR)_ methods [47, 62] restore graph connectivity through local reconnections, based on the intuition that neighbors of neighbors are likely to remain close to the affected node. Compared with RBR, NRBR may degrade index quality while achieving higher update throughput. However, in Pareto-frontier-based DVQ indices, these NRBR methods cannot guarantee that the neighbors of a node’s neighbors belong to its Pareto frontiers, making it difficult to maintain high retrieval accuracy.
