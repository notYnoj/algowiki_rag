_Sub-step 2a (dispatch and compile-time reads)._ With bits(mem\[0\]) in the residual stream, a constant- depth MLP computes the match bit \(\delta_p=^\text{def}\unknown[\text{bits}(\text{mem}[0])=\text{bits}(p)]\) for every program address \(p\in\{0,\dots,P-1\}\). The weights of _T_ contain _P_ head groups H<sub>0</sub>_,...,_H<sub>_P_-1</sub>, one per program line; each H_<sub>p</sub>_ issues, in parallel, one indexed read (Lem. 12) for every compile-time address in _I<sub>p</sub>_’s descriptor. All _P_ groups run as parallel heads within the same two attention layers; an MLP gated by \(\delta_p\) then copies the active group’s results into shared operand slots.

_Sub-step 2b (runtime reads)._ For each runtime address listed in _I<sub>p</sub>_’s descriptor (the value bits(_a_) for a mem\[_a_\] or `inp`\[_a_\] access), bits(_a_) is now available in the residual stream from Sub-step 2a. A second indexed read uses bits(_a_) as the query: Lem. 12 for mem\[_a_\], or a direct positional attention to input position _a_ for `inp`\[_a_\]. By the _flat_ Word RAM constraint, no runtime address is itself memory-indirect, so two more attention layers suffice. After Block 2 every operand of _I<sub>p</sub>_ resides in its designated residual-stream slot.

**Block 3: Execute Instruction (Prop. 5).** With all operands in the residual stream, a single constant- depth MLP computes the _w_-bit destination value bits(_v_) and the next `pc` value \(\text{bits}(\text{\texttt{pc}}')\), placing both into dedicated result slots. For instructions whose result is a _w_-bit function of _w_-bit operands (bitwise, +, -, \(\checkmark\), \(\gg\), comparisons, conditional moves, branch-target arithmetic), Block 3 implements the operation as an AC<sup>0</sup> circuit and uses no attention. For \(\times\), \(\div\), mod, Block 3 executes _one inner iteration_ of the corresponding long-multiplication or long-division algorithm; the per-iteration intermediates (partial product, remainder, quotient, phase counter) live in program-private memory cells, so they are read and written like any other word and the simulator-level treatment is unchanged (Prop. 7).

**Block 4: Store Results (Prop. 6).** Block 4 appends, to the transcript, the memory blocks committed by the active instruction: a `mem` # bits(_a<sub>d</sub>_) # bits(_v_) block for each address _a<sub>d</sub>_ that _I<sub>p</sub>_ writes (typically the destination plus the updated `pc`), followed by a closing &. The transformer’s weights are shared across positions, so Blocks 1-3 _run_ at every position; their reads are reliable, however, only at & positions, where the rightmost-match reads see exclusively committed memory blocks from _prior_ steps. At any non-& position within the current step’s serialization, a rightmost-match read for the destination address _a<sub>d</sub>_ would retrieve the freshly (and partially) written value of the current step rather than its operand-time value. Block 4 sidesteps this by ignoring the local outputs of Blocks 1-3 at non-& positions and instead attending to the most recent &, copying the snapshot (the addresses to be written and the corresponding result bits) that Blocks 1-3 produced at that &. Concretely: at the & position itself, Block 4 emits the first token of the next step’s serialization (the `mem` token of the first memory block); at each of the following _Cw+D_-1 positions, an attention head attends to the rightmost & at position _s_<sub>&</sub>, an MLP computes the offset \(\delta=^\text{def}t-s_\&\in\{1,\dots,Cw+D\}\), and a constant-depth MLP selects the appropriate \(\delta^\text{th}\) token of the serialization (a `mem` marker, a # marker, an address bit, a value bit, or the closing &) from the snapshot via one-hot extraction (Svete and Cotterell, 2024, Lem. B.1). When the offset hits a block boundary, the next memory block’s `mem` and # tokens are emitted; when all blocks have been written, the closing & is emitted, at which point Blocks 1-3 will again run on a clean prefix and produce the snapshot for the next step.

**Token count.** Each Word RAM step writes a constant number _K_ of memory blocks (depending only on the program, not the input), so

\(Cw+D=2Kw+3K+1\)

tokens are emitted per step (each block is `mem`, two #s, and 2_w_ bit tokens; one closing &). For instructions whose semantics is a single AC<sup>0</sup> operation (simple-arithmetic class) this is O(_w_) per step. For \(\times\)/\(\div\)/mod, the operation is unfolded into _w_ inner iterations, each of which is itself a flat memory-read/write step taking O(_w_) tokens (Prop. 7); the total is therefore O(_w_<sup>2</sup>). Summing over _t_ Word RAM steps gives \(t\cdot\mathcal{O}(w^2)\) CoT tokens, and \(t\cdot\mathcal{O}(w)\) when no \(\times\)/\(\div\)/mod instruction is used.

**Residual stream as a serialized snapshot.** It is instructive to view the residual stream at any CoT position as a structured record with one _w_-dimensional slot per memory block to be emitted by the current step: an address slot and a value slot for each of the _K_ writes. Each CoT token fills one bit of one slot, advancing \(\delta\) through the slots until & marks completion. The CoT transcript is therefore a sequence of `mem`-anchored memory blocks, and the simulator’s job at each step reduces to (i) reading a constant number of `mem` blocks, (ii) computing the new contents, and (iii) appending a constant number of new `mem` blocks.
