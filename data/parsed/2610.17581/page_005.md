### 2.2 Query Model

We can formally define a _cut query_ by \(\mathsf{cut}(S)=w(\partial(S))\), returning the weight of edges crossing the queried set. Often it will be helpful to work not directly with cut but rather with a variety of primitives which can be readily defined in terms of this query. For example, the degree of a vertex can be computed by a single cut query, deg(_v_)=cut({_v_}), and for graphs, the induced degree of _v_ in _S_ can be computed by \(\mathrm{deg}_S(v)=\frac{1}{2}\big(\mathsf{cut}(\{v\})+\mathsf{cut}(S\backslash\{v\})-\mathsf{cut}(S)\big)\). More generally, for two disjoint sets _S_ and _T_, define \(\mathrm{Cross}(S,T)=\frac{1}{2}\big(\mathsf{cut}(S)+\mathsf{cut}(T)-\mathsf{cut}(S\cup T)\big)=w(E(S,T))\).<sup>4</sup> Using the Cross primitive, it is straightforward to randomly sample an edge incident to _v_ using _O_(log_n_) cut queries. At a high level, the idea is to recursively winnow _v_’s potential neighborhood down from _V_\\{_v_}, choosing between two disjoint sets _S_ and _T_ with probability proportional to deg_<sub>S</sub>(v_) and deg_<sub>T</sub>(v_). Splitting the chosen set and repeating this procedure will terminate in a single neighbor _u_ with probability proportional to _w(u,v_) after _O_(log_n_) rounds. As the induced degrees can be computed with two Cross calls, or six cut queries, we can sample a random edge incident to _v_ in _O_(log_n_) cut queries. If the degrees of all vertices are known (either _a priori_ or via _n_ cut queries), selecting _v_ with probability proportional to deg(_v_) yields an edge sampler Rand_<sub>G</sub>_ which returns a uniformly random edge on unweighted graphs, or more generally, returns edge _e_ with probability _w(e)/w(G_).

Unfortunately, for multiple different reasons the procedure for Rand_<sub>G</sub>_ cannot be directly lifted to hypergraphs. In particular, the query Cross(_A,B_) provides no information about the induced hypergraph \(H[A\cup B]\).<sup>5</sup> To address this issue, Chen et al. \[14\] introduce the edge query for hypergraphs, where edge(_S_) returns a random hyperedge in \(\partial(S)\) (distributed proportionally to hyperedge weight). In a similar manner to Rand_<sub>G</sub>_, this allows for the construction (with knowledge of degrees) of an edge sampler for hypergraphs, denoted Rand_<sub>H</sub>_, which samples _e_ with probability proportional to \(|e|\cdot w(e)\). While our main algorithmic results use cut and edge queries, we will also study two further queries introduced in previous work on (hyper)graph reconstruction (e.g., \[19\]): the additive query is defined by add(_S_)=_w(E(S_)), and the edge- detecting query is-edge<sup>?</sup>(_S_) returns the membership of \(S\in E\). We note that add and cut queries are equivalent in graphs, if degrees are known, by the identity \(2\mathsf{add}(S)+\mathsf{cut}(S)=\sum_{v\in S}\mathrm{deg}(v)\).<sup>6</sup>

In general, we will say that the _query complexity_ of a problem is the least number of queries necessary to guarantee a solution to a problem, with probability 1 in the deterministic case, or with probability at least 1-_n_<sup>-_c_</sup> for some positive constant _c_ in the randomized case. A query algorithm is considered _efficient_ if it runs in polynomial time. Lastly, for a maximization problem with optimum value OPT, an algorithm is an \(\alpha\)_-approximation_ if it returns a solution with value at least \(\mathrm{OPT}/\alpha\). By definition, the query complexity of an approximation specifies approximations _w.h.p_.
