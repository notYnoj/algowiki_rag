<tbc>the space complexity of the search data structure, an important consideration in applications. The importance of sparsity motivates the main algorithmic question considered in this paper:

**Problem 1.1** (Sparse \(\alpha\)-Navigable Graph Construction)**.** _Given a dataset P_={_p_<sub>1</sub>_,...,p<sub>n</sub>}, distance function_ \(d(\cdot,\cdot)\)_, and_ \(\alpha\ge 1\)_, return an_ \(\alpha\)_-navigable graph G_=(_P,E_) _with as few edges as possible._

The study of this problem was recently initiated in \[12\] and \[25\]. While constructing the sparsest \(\alpha\)-navigable graph is NP-hard, even for points in Euclidean space \[12\], an _O_(log_n_) approximation can be obtained in _O(n_<sup>3</sup>) time by reframing the problem as _n_ set cover instances (see 2.3 for more details). These recent papers improve this bound. For example, letting \(\mathsf{OPT}_\alpha\) denote the minimum number of edges in any \(\alpha\)-navigable graph for _P_, \[12\] presents an algorithm for constructing an \(\alpha\)-navigable graph with \(O(\mathsf{OPT}_\alpha logn)\) edges that runs in worst-case \(\widetilde{O}(n^{2.5})\) time.<sup>1</sup>

\[25\] gives an even faster algorithm in a **_resource-augmented_** setting. They present an \(\widetilde{O}(n^\omega log(\Delta_P)/\varepsilon)\) time algorithm that computes an \(\alpha\)-navigable graph with \(O(\mathsf{OPT}_{2\alpha(1+\varepsilon)}logn)\) edges, where \(\varepsilon>0\) is any small constant and \(2\le\omega<2.372\) is the exponent of fast \(n\times n\) matrix multiplication. This result is resource-augmented bound because \(2\alpha(1+\varepsilon)>\alpha\), we have that \(\mathsf{OPT}_{2\alpha(1+\varepsilon)}\ge\mathsf{OPT}_\alpha\).<sup>2</sup> Thus, the algorithm returns a graph whose sparsity is within an _O_(log_n_) factor of an objective larger than \(\mathsf{OPT}_\alpha\). Such an algorithm can yield a runtime improvement if \(\mathsf{OPT}_\alpha\in\widetilde{\omega}(n^{\omega-1}log(\Delta_P))\), as other algorithms exist which run in \(\widetilde{\widetilde{O}}(n\cdot\mathsf{OPT}_\alpha)\) time.

## 1.2 How much resource augmentation is too much?

While resource augmentation leads to a clear runtime advantage, reducing graph construction cost from roughly \(\widetilde{O}(n^{2.5})\) time to roughly \(\widetilde{O}(n^\omega)\) time, it is natural to ask how much of a price is paid in terms of graph sparsity. In other words, **how much larger is** \(\mathsf{OPT}_{2\alpha(1+\varepsilon)}\) **than** \(\mathsf{OPT}_\alpha\)**?**

In short, the answer is that the gap between these quantities can be substantial. When constructing \(\alpha\)-navigable graphs for real-world datasets, practitioners tend to set \(\alpha\) close to 1 (usually in the range \[1.0,1.2\]) \[33,34,39,40\]. \(\alpha\) is always chosen less than 2. Recalling that higher \(\alpha\) improves both accuracy and convergence rate, this suggests that even \(\mathsf{OPT}_2\le\mathsf{OPT}_{2\alpha(1+\varepsilon)}\) is too large to be usable. Indeed it has been confirmed experimentally that, on many real-world datasets, as \(\alpha\) grows towards 2, the sparsest \(\alpha\)-navigable graph becomes essentially complete.

One explanation for this is that, while not truly random, many modern high-dimensional vector embedding datasets exhibit properties of random points in Euclidean space. In particular, the majority of vectors are nearly orthogonal to each other, so distances between points tend to be similar. Indeed, in common embedding datasets, the aspect ratio is quite low, with the maximum pairwise distance no more than a small factor of the minimum. In an \(\alpha\)-navigable graph with \(\alpha>2\), any source-target pair requires an edge that gets at least 50% closer to the target. For common datasets, such an edge may simply not exist: the only option is to connect directly to the target. I.e., OPT<sub>2</sub> will be close to _n_<sup>2</sup>.

Given this, the goal of this work is to develop graph construction algorithms that enjoy the same efficient runtime as the method of \[25\], but without sacrificing so much on sparsity. In particular, instead of competing with \(\mathsf{OPT}_{2(1+\varepsilon)\alpha}\), ideally we would return a graph whose sparsity is competitive with the best \((1+\varepsilon)\alpha\)-navigable graph, where \(\varepsilon\) can be set arbitrarily close to zero.

<sup>1</sup>For the special case of \(\alpha=1\), this runtime can be further improved to \(\widetilde{O}(n^2)\), which is essentially optimal under the Strong Exponential Time Hypothesis \[12\]. We also note that for general \(\alpha\), the method actually runs in \(\widetilde{O}(min(n\cdot\mathsf{OPT}_\alpha,n^{2.5}))\), so can be faster than \(\widetilde{O}(n^{2.5})\) if \(\mathsf{OPT}_\alpha=o(n^{1.5})\). <sup>2</sup>Prior work uses the term **_bicriteria_** to refer to these algorithms. We prefer to use the term _resource-augmented_ since there are in fact not two criteria being optimized. Rather, we our goal is to return a graph whose size is competitive with the sparsest graph satisfying a slightly stricter set of constraints.
