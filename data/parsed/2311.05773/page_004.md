A generic state of InversionSort will be defined using a _backbone_, which is a sequence of compared elements of alternating colors, called _representatives_ or _pivots_. Each representative will be assigned a _bucket_, which is a set of elements of the same color, that lie between the two neighboring representatives of the other color on the backbone. This backbone is refined if new inversions are found, giving the algorithm its name. This leads to a ternary _refinement tree_, where every node stands for a subproblem that was split in three by finding a new inversion. In this first (and only interesting) phase of the algorithm, monochromatic comparisons are only used to increase the probability of finding an inversion or to verify that no further inversions exist. Here, we use a classical technique of balancing costs that does for each red-red comparison \(\alpha\) bichromatic comparisons, and for each blue-blue comparison \(\beta\) bichromatic comparisons

We first develop some notation to better explain InversionSort and explain how the algorithm works. We summarize this discussion in pseudocode as Algorithm 1. For simplicity of exposition, we add an artificial smallest red element and an artificial largest blue element to the input. Doing comparisons with these artificial elements does not incur any cost.

InversionSort makes progress from one state to the next by performing three steps: a) finding an _inversion_ (which we define soon) between neighboring representatives on the backbone, b) inserting this inversion on the backbone, and c) pivoting with these two elements, thereby refining the buckets.

**Definition 2.** _\[Backbone, Representatives, and Buckets\] The backbone consists of a totally ordered, alternating list of_ representatives (_u_<sub>0</sub>_,u_<sub>1</sub>_,u_<sub>2</sub>_,...,u_<sub>2_k_</sub>_,u_<sub>2_k_+1</sub>)=(_r_<sub>0</sub>_,b_<sub>1</sub>_,r_<sub>2</sub>_,...,r_<sub>2_k_</sub>_,b_<sub>2_k_+1</sub>)_, where_ \(r_{2i}\in R\) _and_ \(b_{2j+1}\in B\) _with r<sub>i</sub>\<b_<sub>_i_+1</sub> _and b<sub>i</sub>\<r_<sub>_i_+1</sub>_. Here, r_<sub>0</sub> _is an artificial red element that is smaller than all elements, and the last element b_<sub>2_k_+1</sub> _is an artificial blue element that is larger than all elements. The representatives define the_ buckets (_X_<sub>0</sub>_,X_<sub>1</sub>_,X_<sub>2</sub>_,...,X_<sub>2_k_</sub>_,X_<sub>2_k_+1</sub>)=(_R_<sub>0</sub>_,B_<sub>1</sub>_,R_<sub>2</sub>_,...,R_<sub>2_k_</sub>_,B_<sub>2_k_+1</sub>) _by_ \(R_i=\{x\in R|b_{i-1}<x<b_{i+1}\}\backslash\{r_i\}\) _and_ \(B_i=\{x\in B|r_{i-1}<x<r_{i+1}\}\backslash\{b_i\}\)_. Here, as a convention, the representative is not included in the bucket. Again,_ \(R_0=\{x\in R|x<b_1\}\) _and_ \(B_{2k+1}=\{x\in B|r_{2k}<x\}\) _are special cases._

**Definition 3.** _\[active subproblems and buckets\] As long InversionSort did not create a certificate that there are no further inversions between x<sub>i</sub> and x_<sub>_i_+1</sub>_, the_ subproblem _defined by the buckets X<sub>i</sub> and X_<sub>_i_+1</sub> _is called active, and so are X<sub>i</sub> and X_<sub>_i_+1</sub>.

From now on, we will use _u<sub>i</sub>_ and _X<sub>i</sub>_ when we don’t care about the color of the _i_th representative and bucket, otherwise we will switch to _r<sub>i</sub>/b<sub>i</sub>_ and _R<sub>i</sub>/B<sub>i</sub>_. We observe that the buckets of two non-adjacent representatives on the backbone are ordered in the same way as the representatives:

**Lemma 4.** _Let X<sub>i</sub> and X<sub>j</sub> be buckets (of arbitrary color) and assume_ \(i+1\le j-1\)_. Then for all_ \(x\in X_i\) _and_ \(y\in X_j\) _we have x\<y._

_Proof._ By definition, _x\<u_<sub>_i_+1</sub>, and _u_<sub>_j_-1</sub>_\<y_. If _i_+1_\<j_-1, then _u_<sub>_i_+1</sub>_\<u_<sub>_j_-1</sub> is implied by transitivity on the backbone, otherwise _u_<sub>_i_+1</sub> is the same element as _u_<sub>_j_-1</sub>. In either case, we get that \(x<u_{i+1}\le u_{j-1}<y\).
