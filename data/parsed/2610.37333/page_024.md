Finally, boundary conditions are attached to each field, selected by node index on a grid or by named tags on a mesh, with `diff-soup` providing the standard linear and nonlinear boundary conditions such as Dirichlet, Neumann, Robin, periodic, and flux boundary conditions.

For more complex workflows, we provide additional modeling features for declaring global constraints, externally controlled inputs, and learnable parameters or parameterized functions. For nonlocal constraints, such as prescribed domain or boundary integrals, the user declares global algebraic variables and a corresponding global constraint to close the system. Since constraints couple densely, we handle global variables using the Schur complement, as described in Section 2.2, to avoid compromising local sparsity. We also provide controls for external forcing protocols in two forms, a direct control for an input variable read inside the equations and a derived control for a quantity the solver assemblies. Furthermore, for differentiable simulation we require the user to mark explicitly which parameters and parameterized functions are learnable, and optionally specify box bounds for the optimizer.

Internally, spec.build() lowers the Recipe to an internal representation that provides the residual, sparse Jacobian, learnable parameters, and controls to the solver. By default, an equation closure returns the right-hand side of the mass-matrix form of Eq. (2), and if an equation uses the symbolic time derivative of a field, the fully implicit form of Eq. (1) is used. For advanced use cases, mass-matrix and implicit problems can be authored directly from the residual and sparsity pattern.
