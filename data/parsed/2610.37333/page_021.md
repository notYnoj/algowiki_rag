Beyond smooth trajectories, the control state _z(t_) introduces events, such as protocol switches and state-triggered conditions, that stop the integration, update the state, and restart it from a consistent state. Because the frozen- controller assumption fixes the time grid, the discrete computational graph alone would miss how the switch time moves with the parameters, so we attach custom JVP and VJP rules to each event. These rules differentiate the switch time by the implicit function theorem and carry its shift into the restarted trajectory, so tangents and cotangents pass through an event as through any accepted step of Figure 2. At transversal crossings, the resulting derivatives match the classical event sensitivities of Galán et al. [90] and Hiskens and Pai [91] and their adjoint counterparts [92] This machinery is required for future applications in control protocol design, where the optimization variables move the events themselves.

Finally, we support the computation of discrete second-order sensitivities, which second-order optimization methods for Eq. (9) consume as Hessian- vector products or as the assembled Hessian. We implement three second- order compositions through the solver: forward-over-forward differentiation, which propagates second-order tangents along the realized trajectory and assembles the full \(n_\theta\times n_\theta\) Hessian at \(O(n_\theta^2T(n))\), reverse-over-forward differentiation, which computes gradients of scalar criteria built from the solution and its forward sensitivities through one reverse sweep over the tangent solve at \(O(n_\theta T(n))\), and forward-over-reverse differentiation, the canonical strategy for Hessian-vector products [67], which differentiates the checkpointed gradient in forward mode and delivers each product at a constant multiple of the gradient cost, \(O(T(n)+n_\theta)\), so Newton-type methods extract curvature without ever assembling the Hessian.

## 3. diff-soup Software Overview

In this section, we introduce the architecture of `diff-soup`, specifically the three primary modules for modeling, simulation, and inference as visually outlined in Figure 3. The modeling module provides the tools for declaring a PDE system, its geometry, and its discretization method through `diff-soup`’s Recipe API to construct a sparse, discrete problem for the time- integrators. The simulation module integrates this system in time using the stiff VSVO algorithms and provides discrete parameter sensitivities. Finally, the inference module solves PDE-constrained optimization problems to learn model parameters from data.
