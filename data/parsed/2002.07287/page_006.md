## 6 Sorting and Ranking of Self-Delimiting Numbers and Outerplanar Graph Isomorphism

For all digits _d_, iterate over all values stored at digit _d_ of the numbers of the current area _A<sub>i</sub>_. For each element \(\ell\) of the alphabet that occurs at digit _d_, increment the `occ`-value of the tuple on top of the stack that is stored at index \(\ell\), or insert a (_d,_1) if it is the first occurrence of \(\ell\) at digit _d_, indicated by a missing entry of \((d,\cdot)\) at the top of the stack. After both iterations have finished, each stack is sorted such that, for two elements _e_<sub>1</sub>=(_d_<sub>1</sub>,`occ`<sub>1</sub>) and _e_<sub>2</sub>(_d_<sub>2</sub>,`occ`<sub>2</sub>) on the stack, it holds that _e_<sub>1</sub> comes before _e_<sub>2</sub> exactly if _d_<sub>1</sub>_\<d_<sub>2</sub>. Note that \(d_1\neq d_2\) for all distinct elements _e_<sub>1</sub> and _e_<sub>2</sub> on the stack.

Next, we show how to construct simultaneously the prefix-sum array for each digit. During the construction of the arrays, we initially maintain the prefix-sum arrays as lists. In detail, we maintain an array _P_ indexed by values \(\ell\in\mathcal{A}\) that stores at \(P[\ell]\) a list storing tuples (_d,_`pre`) representing the elements of the prefix-sum arrays. During the construction we store in a temporary array \(P'\) for each digit _d_ the current prefix-sum while iterating over all table entries of _T_. Iterate over all entries of _T_, and when encountering a non-empty stack at \(T[\ell]\), pop all elements of the stack. For each (_d,_`occ`) value removed, increment \(P'[d]\) by `occ`, and append \((d,P'[d])\) to \(P[\ell]\).

Once this procedure is finished, the prefix-sum array for each _d_ can be obtained via the lists stored in _P_. Consider a round of the sorting algorithm where we sort by digit _d_. When encountering some \(\ell\in\mathcal{A}\) during the iteration over the digits of all numbers of the current area, we look at \(P[\ell]\) to find the prefix-sum value (_d,_`pre`) as the first entry of the list stored at \(P[\ell]\). As described, we replace (_d,_`pre`) with (_d,_`pre`-1) and continue with the round. Once a round is finished, we remove the first element of each accessed list, i.e., all tuples \((d,\cdot)\). We so have the information for digit _d_+1 as the first entries of the lists in _P_ that are read during the sorting round for _d_+1.

We now analyze the space-bound and runtime of maintaining the tables and prefix-sum arrays over all areas. Note that there are _O_(log_N_) areas. For each area, we use \(O(2^{\tau/2}\tau)\) bits to store the table _T_, excluding the space used for the stacks. The _k<sub>i</sub>_ numbers of an area _A<sub>i</sub>_ contain \(O(k_i+N_i/\tau)\) digits, and thus we can store the stacks of the table _T_ and the arrays _P_ and \(P'\) with \(O(k_1+N_1/\tau\cdot\tau+k_2+N_2/\tau\cdot\tau+\dots)+o(2^\tau)=O(N)+o(2^\tau)\) bits. We now analyze the runtime. For each area, we construct an empty table _T_ in time \(O(2^{\tau/2})\) and scan over all digits of all numbers of the current area. The prefix-sum arrays of an area _A<sub>i</sub>_ are constructed by another linear scan over the tables and digits, i.e., in time \(O(k_i+N_i/\tau)\) time. Over all areas, the time spent on constructing the prefix-sum arrays is bound by \(O(k+N/\tau)+o(2^\tau)\).

We now analyze the space-bound and runtime of the rest of the algorithm. The bit-vectors _B_ and _C_ use \(O(f(m)logN)=O(N/\tau logN)=O(N/logN\cdot logN)=O(N)\) bits and \(S'\) uses _O(N_) bits. Scanning through _S_, while computing and filling _C_ and _B_ can be done in \(O(k+N/\tau)=O(k+N/logN)\) time. (Roughly speaking, we can scan _S_ in \(O(N/\tau)\) time and, to handle each number separately, costs us us _O(k_) extra time in total.)

Recall that after resorting the numbers in areas, _A<sub>i</sub>_ has _k<sub>i</sub>_ self-delimiting numbers stored subsequently in _N<sub>i</sub>_ bits. Sorting _A<sub>i</sub>_ runs in \(O(N_i/\tau+k_i+k_i\frac{i}{\tau})\) time since reading _A<sub>i</sub>_ and reading every number runs in \(O(N_i/\tau+k_i)\) time and the digit-wise sorting runs in \(O(k_i\frac{i}{\tau})\) time. Over all areas the running time is \(O(\sum_{i\in[1,f(m)]}(N_i/\tau+k_i+k_i\frac{i}{\tau}))=O(\sum_{i\in[1,f(m)]}(N_i/\tau+k_i))+O(\sum_{i\in[1,f(m)]}k_i\frac{i}{\tau})=O(N/\tau+k)\) time.

In summary, the stable sorting algorithm runs in \(O(N/\tau+k)+o(2^\tau)\) time and \(O(N)+o(2^\tau)\) bits. \(\blacktriangleleft\)
