\(\blacktriangleright\) **Theorem 4.** _Given an N-bit sequence S of k self-delimiting numbers and a parameter_ \(\tau\) _with_ \(logN\le\tau\le w\) _there is a stable-sorting algorithm computing a bit sequence of N bits that stores the given self-delimiting numbers in sorted order. The algorithm runs in time_ \(O(k+N/\tau)+o(2^\tau)\) _and_ \(O(N)+o(2^\tau)\) _bits._

**Proof.** The idea is to put the numbers of _S_ that are at most \(q=2^{N/\tau}\) into a sequence \(S_{\le q}\) and sort it by using Lemma 3. We write the remaining \(O(\frac{N}{logq})=O(\tau)\) numbers into a sequence _S<sub>\>q</sub>_ where we interpret each number as a string of digits out of the alphabet \(\Sigma=\{0,\dots,2^{\tau/2}\}\) stored as self-delimiting numbers. To sort _S<sub>\>q</sub>_ we first sort the numbers by their length in bits into areas and then sort the areas independently. The difference to the previous lemma is that the numbers are big, and thus we cannot move a number in constant time. The new approach comes from string sorting. We create a sequence of pairs, where the _i_th pair consists of the length in bits and the position of the _i_th number of _S<sub>\>q</sub>_, respectively. Instead of sorting the numbers, we sort the pairs by their first component (i.e., by the length in bits) utilizing counting sort. By sequentially reading the pairs we can access each number in _S<sub>\>q</sub>_ using the second component of the pair and write all numbers into a sequence \(S'_{>q}\) in order of their length. Now we can sort the numbers area-wise employing radix-sort. Assume that we sort area _A<sub>i</sub>_ that consists of numbers that all consist of _i_ bits. Again, instead of reading the whole self-delimiting number, we interpret them as strings of \(\lceil i/\lceil\tau/2\rceil\rceil\) digits and sort the tuples by the \(d=1,\dots,\lceil i/\lceil\tau/2\rceil\rceil\) digit of the numbers, starting with the least significant digit. After sorting \(S_{\le q}\) and _S<sub>\>q</sub>_ we can write them into a single _N_-bit sequence and return it as the result.

We now consider the space consumption of the algorithm above. The sequence of tuples uses \(O(\tau logN)\) bits. During the algorithm we write the self-delimiting numbers in _N_-bit sequences. The application of counting sort on digits of \(\lceil\tau/2\rceil\) bits requires tables with \(2^{\lceil\tau/2\rceil}\) entries, each of \(O(\tau)\) bits. The tables use \(o(2^\tau)\) bits. Together with the application of Lemma 3 our algorithm uses \(O(N)+o(2^\tau)\) bits in total.

Sorting the numbers by their length runs in \(O(\tau)\) time using counting sort. Sorting an _N<sub>i</sub>_ bit area storing _k<sub>i</sub>_ self-delimiting numbers, each of _i_ bits, runs in \(O(k_ii/\tau)\) time. Over all existing areas the algorithm runs in \(O(\sum_ik_ii/\tau)=O(k+N/\tau)\) time. Together with Lemma 3 this results in a runtime of \(O(k+N/\tau)+o(2^\tau)\). \(\blacktriangleleft\)
