and applying the algorithm at the block level. In this context, each scalar multiplication in the original "base-case" algorithm becomes a matrix multiplication of size \((m/m_0)\times(k/k_0)\) by \((k/k_0)\times(n/n_0)\), assuming for simplicity that _m_<sub>0</sub>, _k_<sub>0</sub>, and _n_<sub>0</sub> divide _m_, _k_, and _n_, respectively. This procedure can then be used to handle the smaller block multiplications, continuing recursively either until the base case \(m_0\times k_0\) by \(k_0\times n_0\) is reached or, more commonly, until the block size is small enough to handle with classical matrix multiplication. The result is a (general) matrix multiplication algorithm of complexity _O_((_mkn_)<sup>log<sub>_m_<sub>0</sub>_k_<sub>0</sub>_n_<sub>0</sub></sup>(_t_)</sup>), where _t_ is the number of scalar multiplications in the base-case routine. When _m=n=k_, this simplifies to \(O(n^\omega)\) for \(\omega=3log_{m_0k_0n_0}(t)\). Throughout, we use \(\langle m,k,n\rangle\) and \(\langle m,k,n;t\rangle\) to refer, respectively, to \(m\times k\) by \(k\times n\) matrix multiplication and an algorithm for it that uses _t_ scalar multiplications.

The above observations underpin one branch of research on fast matrix multiplication, which is focused on searching for optimal routines for small matrices \[3,24,28,39,41,44,47,49,50,55,56\], where "optimality" is measured by the number of scalar multiplications used. Algorithms derived this way are sometimes referred to as _feasible_ fast matrix multiplication because, while they typically do not achieve the best known upper bounds on \(\omega\), they are applicable to inputs of more manageable size, making them candidates for practical use.<sup>1</sup> Accordingly, significant effort has been placed on optimizing these routines beyond their asymptotic complexity (see \[32\]).

The search for small matrix multiplication routines led to the discovery of Arbitrary Precision Approximate or APA matrix multiplication algorithms in the late 70’s. First coined by Bini et al. \[10\], APA matrix multiplication refers to a class of bilinear algorithms that, given input matrices _A_ and _B_ and an evaluation parameter \(\varepsilon\), computes

\(AB+\varepsilon R_1+\varepsilon^2R_2+\cdots+\varepsilon^dR_d,\) (1.2)

where _R_<sub>1</sub>_,...,R<sub>d</sub>_ are residual matrices (that depend on _A_ and _B_) and _d_ is the _degree_ of the algorithm. Note that the approximation obtained from an APA routine can be made arbitrarily accurate by taking \(\varepsilon\rightarrow 0\). An example of an APA algorithm for multiplying \(3\times 2\) and \(2\times 2\) matrices - alongside both classical and fast exact alternatives - is shown in Figure 1, which in particular emphasizes how each algorithm obtains its output (exact or approximate) from a certain number of scalar multiplications.

From Figure 1 we see that APA matrix multiplication can (at least in some cases) be accomplished with fewer scalar products than exact matrix multiplication. In fact, Hopcroft and Kerr \[34\] showed that computing the exact product of a \(3\times 2\) and \(2\times 2\) matrix requires at least 11 scalar multiplications and hence that no exact algorithm is capable of beating the 10 multiplication APA routine of Bini et al. \[10\]. One way to understand this is through the lens of tensor decomposition; exact and APA algorithms for \(m\times k\) by \(k\times n\) matrix multiplication can be interpreted as exact and approximate decompositions of the \(\langle m,k,n\rangle\) matrix multiplication tensor, which is defined as

\(\mathcal{M}_{\langle m,k,n\rangle}:=\sum_{i_1=1}^m\sum_{i_2=1}^k\sum_{i_3=1}^nE_{i_1i_2}^{(m,k)}\otimes E_{i_2i_3}^{(k,n)}\otimes E_{i_3i_1}^{(n,m)}.\) (1.3)

Here, \(\otimes\) is the Kronecker product and \(E_{ij}^{(m,n)}\) is an \(m\times n\) standard basis matrix, whose only nonzero entry is a one in row _i_ and column _j_.<sup>2</sup> Each scalar multiplication in an exact/APA algorithm contributes a rank-one tensor (e.g., one term in the sum (1.3)) to the corresponding decomposition of \(\mathcal{M}_{\langle m,k,n\rangle}\). Accordingly, the number of scalar multiplications in an exact algorithm provides an upper bound on the _rank_ of \(\mathcal{M}_{\langle m,k,n\rangle}\), that is, the minimum number of rank-one tensors needed to construct \(\mathcal{M}_{\langle m,k,n\rangle}\). The same can be said of an APA algorithm and the _border_ rank of \(\mathcal{M}_{\langle m,k,n\rangle}\), which corresponds to the minimum number of rank-one tensors in a sequence of decompositions whose limit is \(\mathcal{M}_{\langle m,k,n\rangle}\). In this language, the above example can be summarized as follows: the rank and border rank of \(\mathcal{M}_{\langle 3,2,2\rangle}\) are 11 and 10 respectively,<sup>3</sup> and corresponding decompositions can be obtained from the algorithms in Figure 1. For more background on tensor (border) rank and the notation used here, see \[42\] and \[8, Section 2\].
