<tbc>case that support paths that cross must cross at least twice. We cannot "commit" a demand to a particular face up front. Consider if a demand _h_ fits into two different faces _F_<sub>1</sub> and _F_<sub>2</sub>, but there are demands _h_<sub>1</sub> and _h_<sub>2</sub> that fit those respective faces and cross _h_ in those faces. If we add leaves into _F_<sub>1</sub>, then we can "uncross" support paths for _h_ and _h_<sub>2</sub>, however we cannot uncross support paths between _h_ and _h_<sub>1</sub>, and vice versa.

We take the following approach. Begin with a feasible flow _z_ that we want to uncross. We temporarily "commit" each demand to one of the faces it fits (if multi-faced, choose arbitrarily). We accept for now that flow paths of demands committed to the same face may cross, but compute a flow _x_ so that demands committed to different faces do not cross. In fact we aim for a more strict condition on _x_: we show how to find _x_ so that, if we define _x<sup>F</sup>_ as the multiflow corresponding to demands committed to face _F_, the _x<sup>F</sup>_’s are "uncoupled" from each other. Here, "uncoupled" is a structural property (defined precisely below) which guarantees that if we can uncross each _x<sup>F</sup>_ separately, regardless of how we do so, we can still safely glue the resulting flows back together without introducing crossing. Then we can just focus on uncrossing each _x<sup>F</sup>_ inductively/recursively. We now make this "committing" process and "uncoupled" property precise.

**Definition 3.4** (Facial Decomposition)**.** Let (_G,H,u,d_) be a facial multiflow instance. Let F be the set of faces of _G_. A _facial decomposition_ is a collection \((H_F:F\in\mathcal{F})\) of subgraphs of _H_ indexed by _F_ such that:

• \((E(H_F):F\in\mathcal{F})\) forms a partition of _E(H_), and<tbc>

• for every face \(F\in\mathcal{F}\), every demand \(h\in E(H_F)\) fits _F_ (but cannot necessarily all be embedded simultaneously in _F_ without crossing).

For a facial decomposition \((H_F:F\in\mathcal{F})\) and a feasible flow _x_, we let _x<sup>F</sup>_ be the portion of _x_ used to route _H<sub>F</sub>_. Note that if \(h\in E(H)\) is multi-faced, the facial decomposition still only puts _h_ into one of the _H<sub>F</sub>_’s. Now we define the "uncoupled" condition and show that we can find a flow satisfying this property. We let supp(_x<sup>F</sup>_) to denote the set of support paths for the flow _x<sup>F</sup>_, and let _G_\[supp(_x<sup>F</sup>_)\] denote the graph induced by the edges in those support paths.

**Definition 3.5** (Nested Supports Property)**.** Let (_G,H,u,d_) be a facial multiflow instance, and let \((H_F:F\in\mathcal{F})\) be a facial decomposition. For a flow _x_ and a face _F_, we define the _stellated support graph G_\[_x,F_\] as follows: begin with the support graph _G_\[supp(_x<sup>F</sup>_)\], add a node _v<sub>F</sub>_ into the interior of _F_, and then for each demand \((s,t)\in E(H_F)\) add edges (_s,v<sub>F</sub>_) and (_t,v<sub>F</sub>_), embedded (without crossing) in the face _F_. We say _x_ satisfies the _nested supports property_ if for every pair of distinct faces \(F_1,F_2\in\mathcal{F}\), the graph _G_\[_x,F_<sub>1</sub>\] is entirely contained within a single face of the graph _G_\[_x,F_<sub>2</sub>\], and vice versa.

**Lemma 3.6.** _Let_ (_G,H,u,d_) _be a facial multiflow instance that is feasible, and let_ \((H_F:F\in\mathcal{F})\) _be a facial decomposition. There exists a feasible flow x satisfying the nested supports property._

The proof of this lemma is slightly tricky to make rigorous, so we include only a sketch here. The full proof appears in the appendix (see Section A.3).

_Proof Sketch of Theorem 3.6._ We augment the instance by adding leaves into the faces: for every face _F_ and demand \(h=(s,t)\in E(H_F)\), add nodes _s<sub>h</sub>,t<sub>h</sub>_ into the face _F_ and supply edges (_s<sub>h</sub>,s),(t<sub>h</sub>,t_) of capacity equal to _d(h_), and move the demand _h_ from (_s,t_) to (_s<sub>h</sub>,t<sub>h</sub>_). We keep the same facial decomposition. We now invoke Theorem 3.3 and obtain a feasible flow _x_ that is almost-uncrossed for this new instance. It is not hard to show that for support paths _P_<sub>1</sub>_,P_<sub>2</sub> associated with distinct faces, if we consider the embedded cycles _C(P_<sub>1</sub>)_,C(P_<sub>2</sub>) obtained by joining the endpoints of the respective paths with their respective demand edges, that these cycles do not cross (though if the paths are associated with the same face, they may cross).

Now, for each face _F_, we let _G<sub>F</sub>_ be the union of _G_\[supp(_x<sup>F</sup>_)\] and all supply edges incident with the face _F_ itself (regardless of whether they are in the support). It is possible to argue that for distinct faces \(F,F'\), _G<sub>F</sub>_ must be contained in a single face of \(G_{F^\prime}\), and vice versa. Once this property is established, we can then argue that the nested supports property holds for the flow _x_.

Assuming such a flow exists, we show that we can focus on uncrossing each face’s flow independently.
