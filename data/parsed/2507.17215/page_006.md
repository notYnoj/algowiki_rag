Recall that if \((u,v)\in E(G_\pi^-)\), then \(\pi(u)\) must be less that \(\pi(v)\) (i.e. _u_ is the source vertex). Therefore, for every \((u,v)\in E(G_\pi^-)\) and \(w\in N_\pi^+(u)\), if \(w\in N(v)\) then we fetch the edge lists _E<sub>u,v</sub>,E<sub>u,w</sub>,E<sub>v,w</sub>_ and execute the above on these lists. Note that since _u_ is the source, the algorithm can iterate only through the temporal edges incident on the source _u_. These are precisely the edges in lists _E<sub>u,v</sub>_ and _E<sub>u,w</sub>_. Similarly, when we fetch the edge lists _E<sub>v,u</sub>,E<sub>v,w</sub>_ and _E<sub>u,w</sub>_(potential choices for edges labeled 1,2 and 3 in Figure-2a), the algorithm can iterate through the temporal edges in the lists _E<sub>u,w</sub>_ and _E<sub>v,u</sub>_ only, since they are the ones incident on the source _u_. Now observe that a single term \(\sigma(u,v)\) appears at most \(|N_\pi^+(s_e)|\) times in this sum, which is upper bounded by \(\alpha\). This leads to the _O(ma_) running time. _Challenge 2:_ For an edge _e_={_u,v_}, \(N(u)\cap N(v)\) can be partitioned into \(N_\pi^+(s_e)\cap N(y_e)\) and \(N_\pi^-(s_e)\cap N(y_e)\). Given a temporal edge _e_=(_u,v,t_), in order to compute the value of the counter _c<sub>e</sub>_, we need to know which vertices in \(N_\pi^+(s_e)\) and \(N_\pi^-(s_e)\) form a \(\delta\)-temporal triangle with _e_. Turns out, it is relatively easy to identify the out-neighbors in \(N_\pi^+(s_e)\), which form a \(\delta\)-temporal triangle with _e_ . The main challenge is dealing with the in-neighbors \(N_\pi^-(s_e)\). Consider \(w\in N_\pi^-(s_e)\). This is equivalent to saying that \(s_e\in N_\pi^+(w)\). Further, if \(w\in N(y_e)\), then \(y_e\in N_\pi^+(w)\) since \(\pi(s_e)<\pi(y_e)\). Since the algorithm iterates over every \((x,y)\in E(G_\pi^-)\) and \(z\in N_\pi^+(x)\), the contribution of _w_ to the value of _c<sub>e</sub>_ will be accounted when considering the edge \((w,s_e)\in E(G_\pi^-)\) and \(v\in N_\pi^+(w)\) i.e. when _w_ is the source vertex. Our goal is find, for each edge in _E<sub>u,v</sub>_, a pair of edges in \(E_{u,w}\times E_{v,w}\) that forms a \(\delta\)-temporal triangle with _w_. However, note that we are no longer allowed to iterate through the edges in the list _E<sub>u,v</sub>_. We can only go over the edges in the lists _E<sub>w,v</sub>_ and _E<sub>w,u</sub>_ since the source vertex is _w_. This is the second challenge, where we would like to determine the edges in _E<sub>u,v</sub>_ that form a \(\delta\)-temporal triangle with _w_, without going over the edges in the list _E<sub>u,v</sub>_ for every \(w\in N_\pi^-(s_e)\).

## 3 \(\exists\exists\forall\) Query

Given a temporal graph _G_=(_V,E_), our goal is to find solutions to the \(\exists\exists\forall\) query mentioned in 1.2.

The algorithm begins by constructing the underlying static graph _G<sub>S</sub>_. This can be done by making a single pass through the edges of _G_. Next, for every static edge \(\{u,v\}\in G_S\), it defines a counter _c<sub>uv</sub>_. The counter _c<sub>uv</sub>_ is used to store the number of common neighbours of _u_ and _v_ in _G<sub>S</sub>_. In order to compute the value of _c<sub>uv</sub>_, the algorithm first determines the lower degree endpoint of the static edge {_u,v_}. Assume _u_ to be this endpoint. Next, it steps through the neighbours of _u_ in _G<sub>S</sub>_. For every \(w\in N(u)\), if _w_ is adjacent to _v_, it increases the value of _c<sub>uv</sub>_ by 1. Finally, the algorithm repeats this procedure for every static edge \(\{u,v\}\in G_S\).

Next, it computes the degeneracy ordering \(\pi\) of _G<sub>S</sub>_, followed by the construction of the directed graph \(G_\pi^-\). Our goal is to compute in-count\[_e_\] and out-count\[_e_\] for every temporal edge _e_.

Broadly speaking, it is relatively easier to determine the value of out-count\[_e_\]. However, similar approach cannot be used to compute in-count\[_e_\]. This is primarily because in \(G_\pi^-\), the out-degree of each vertex is upper bounded by the degeneracy \(\alpha\), however the in-degree can be arbitrarily large. This leads to different ways of dealing with the in-neighbours and out-neighbours, each of which are presented in sections 3.1 and 3.2 respectively.

## 3.1 Dealing with Out-Neighbours

Given an edge \((u,v)\in G_\pi^-\), the goal is to compute out-count\[_e_\] for every temporal edge _e_=(_u,v,t_) (and (_v,u,t_)). We defer the proofs of the theorems in this section to the supplementary material. Note that if \((u,v)\in G_\pi^-\), then \(\pi(u)<\pi(v)\).

The algorithms presented in this section use the following subroutines as primitives:

(1) FindExceedingEntryLS(_L_<sub>1</sub>_,L_<sub>2</sub>):_L_<sub>1</sub> and _L_<sub>2</sub> are lists of temporal edges, sorted in the increasing order of timestamp. The function returns a list _L_<sub>12</sub> of size |_L_<sub>1</sub>|. For every \(e\in L_1\), _L_<sub>12</sub>\[_e_\] stores the index of the first edge in _L_<sub>2</sub> with timestamp at least _t(e_). Further, it does so in time _O_(|_L_<sub>1</sub>|+|_L_<sub>2</sub>|).

(2) FindExceedingEntryBS(_L_<sub>1</sub>_,L_<sub>2</sub>):_L_<sub>1</sub> and _L_<sub>2</sub> are lists of temporal edges, sorted in the increasing order of timestamp. The function returns a list _L_<sub>12</sub> of size |_L_<sub>1</sub>|. For every \(e\in L_1\), the function uses binary search to determine the index of the first edge in _L_<sub>2</sub> whose timestamp exceeds _t(e_). Thus the overall running time of the algorithm is _O_(|_L_<sub>1</sub>|log|_L_<sub>2</sub>|).

(3) FindBoundingentry(_L_<sub>1</sub>_,L_<sub>2</sub>_,y_): As before, _L_<sub>1</sub> and _L_<sub>2</sub> are lists of temporal edges, sorted in the increasing order of timestamp. The function returns a list _L_<sub>12</sub> of size |_L_<sub>1</sub>|. For every \(e\in L_1\), _L_<sub>12</sub>\[_e_\] stores the index of the last edge in _L_<sub>2</sub> with timestamp at most _t(e_)+_y_. This function runs in _O_(|_L_<sub>1</sub>|+|_L_<sub>2</sub>|) time.

Let us fix an edge (_u,v_) in \(G_\pi^-\) and an out-neighbour _w_ of _u_. Assume that _v_ is adjacent to _w_ in _G<sub>S</sub>_. If not, then it is obvious that _w_ cannot form a triangle with _e_. Suppose \(L_1\leftarrow E_{u,v}\). The goal is to compute the value of out-count\[_e_\] for every \(e\in L_1\). Set _L_<sub>2</sub> to _E<sub>u,w</sub>_ and _L_<sub>3</sub> to _E<sub>v,w</sub>_. An edge \(e\in L_1\) forms at least one \(\delta\) temporal triangle with _w_, if there exists a pair \((e_2,e_3)\in L_2\times L_3\) which satisfies \(t(e)\le t(e_2)\le t(e_3)\le t(e)+\delta\). Thus, for an edge \(e\in L_1\), if such a pair exists in \(L_2\times L_3\), then the algorithm increments out-count\[_e_\] by 1. This leads to the following natural question: "How to find such a pair?"

Given _L_<sub>1</sub>_,L_<sub>2</sub> and _L_<sub>3</sub>, the algorithm proceeds as follows (refer algorithm-1):

(1) It invokes FindExceedingEntryLS(_L_<sub>1</sub>_,L_<sub>2</sub>) to get the list _L_<sub>12</sub>. We will abuse notation and use _L_<sub>12</sub>\[_e_\] to denote the index, as well the edge at this index in _L_<sub>2</sub>.

(2) Next, it invokes FindExceedingEntryBS(_L_<sub>2</sub>_,L_<sub>3</sub>) to obtain the list _L_<sub>23</sub>. We will abuse notation and use _L_<sub>23</sub>\[_e_\] to denote the index, as well the edge at this index in _L_<sub>3</sub>.

(3) Finally, for every \(e\in L_1\), it checks whether \(t(e)\le t(L_{12}[e])\le t(L_{23}[L_{12}[e]])\le t(e)+\delta\). If this condition holds, then it increments out-count\[_e_\] by 1. Otherwise, it proceeds to the next edge of _L_<sub>1</sub>.

The following theorem shows that _e_ forms a \(\delta\)-temporal triangle with _w_ if and only if (_e,L_<sub>12</sub>\[_e_\]_,L_<sub>23</sub>\[_L_<sub>12</sub>\[_e_\]]) form a \(\delta\)-temporal triangle.
