## 2.2 String Relations

A _string relation_ (_over_ \(\Sigma\)) is a subset of \(\Sigma^*\times\Sigma^*\). For any string relation \(\unknown\) and \(w\in\Sigma^*\) we define \(\Lambda_\unknown(w)=\{u\in\Sigma^*|u\unknown w\}\), i.e., the set of all strings that are in the \(\unknown\) relation to _w_; we also lift this notation to languages \(L\subseteq\Sigma^*\), i.e., \(\Lambda_\unknown(L)=\bigcup_{w\in L}\Lambda_\unknown(w)\). Next, we define several well-known string relations.<sup>2</sup>

The _prefix_ and _infix relations_ are denoted by \(\unknown_\text{pre}\) and \(\unknown_\text{in}\): formally, we write \(u\unknown_\text{pre}w\) when _uv=w_ for some \(v\in\Sigma^*\) and we write \(u\unknown_\text{in}w\) when \(vuv'=w\) for some \(v,v'\in\Sigma^*\). The _left- extension_ and _extension relations_ are denoted by \(\unknown_\text{text}\) and \(\unknown_\text{ext}\): formally, we write \(u\unknown_\text{text}w\) when _u=vw_ for some \(v\in\Sigma^*\) and write \(u\unknown_\text{ext}w\) when \(w\unknown_\text{in}u\). The _subsequence_ and _supersequence relations_ are denoted by \(\unknown_\text{sub}\) and \(\unknown_\text{sup}\): we write \(u\unknown_\text{sub}w\) when _w_\[_j_<sub>1</sub>\]_w_\[_j_<sub>2</sub>\]_...w_\[_j_<sub>|_u_|</sub>\]=_u_ for some \(1\le j_1<j_2<\dots<j_{|u|}\le|w|\), and write \(u\unknown_\text{sup}w\) when \(w\unknown_\text{sub}u\). Note that we do not study the suffix and right-extension relations because they amount to prefix and left-extension up to mirroring the strings.

## 2.3 Problem Statement: The \(\unknown\)-Matching Problem

The well-known _regex matching_ problem is to decide whether \(w\in\mathsf{L}(r)\) for a given regular expression _r_ and input string _w_. As explained above, this generalises to the \(\varepsilon\)NFA acceptance problem, where we want to decide whether \(w\in\mathsf{L}(A)\) for a given \(\varepsilon\)NFA _A_ and input string _w_. In this paper, we study the \(\unknown\)_-matching problem_, where \(\unknown\) is one of the string relations presented above: For a given string \(w\in\Sigma^*\) and an \(\varepsilon\)NFA _A_, decide whether _A_ accepts a string _u_ with \(u\unknown w\), i.e., decide whether \(\Lambda_\unknown(w)\cap\mathsf{L}(A)\neq\emptyset\).

We also define _quantitative_ variants of this matching problem. For a string relation \(\unknown\), the _min-variant of the_ \(\unknown\)_-matching problem_ is as follows: For a given string \(w\in\Sigma^*\) and an \(\varepsilon\)NFA _A_, compute a shortest string _u_ with \(u\unknown w\) and \(u\in\mathsf{L}(A)\), or report that no such string _u_ exists. The _max-variant of the_ \(\unknown\)_-matching problem_ is as follows: For a given string \(w\in\Sigma^*\) and an \(\varepsilon\)NFA _A_, either report that there are arbitrarily long strings _u_ with \(u\unknown w\) and \(u\in\mathsf{L}(A)\), or compute a longest string _u_ with \(u\unknown w\) and \(u\in\mathsf{L}(A)\), or report that no such string _u_ exists. Further, all lower bounds on the quantitative variants of the matching problem will already apply in the setting where we are only required to compute the length of the witnessing string.

Finally, we define a _universal_ variant of the matching problem. For a string relation \(\unknown\), the _universal-variant of the_ \(\unknown\)_-matching problem_ is as follows: For a given string \(w\in\Sigma^*\) and an \(\varepsilon\)NFA _A_, decide whether _A_ matches all strings _u_ with \(u\unknown w\), i.e., decide the inclusion problem \(\Lambda_\unknown(w)\subseteq\mathsf{L}(A)\).

Finally, note that if we choose \(\unknown\) to be the string equality relation, then all the problem variants from above are just the same as the classical regex matching problem.

## 2.4 Computational Model and Basic Input-Preprocessing

The computational model we use to state our algorithms is the standard unit-cost word RAM with logarithmic word-size \(\omega\) (meaning that each memory word can hold \(\omega\) bits). It is assumed that this model allows processing inputs of size _n_, where \(\omega\ge logn\); in other words, the size _n_ of the input never exceeds (but, in the worst case, is equal to) \(2^\omega\). Intuitively, the size of the memory word is determined by the processor, and larger inputs require a stronger processor (which can, of course, deal with much smaller inputs as well). Indirect addressing and basic arithmetical or bitwise operations on such memory words are assumed to work in constant time. This is a standard computational model for the analysis of algorithms, defined in \[FW93\]. To make some of our algorithms faster, it may be necessary to allocate large arrays in constant time: for this, we use the standard technique of lazy initialisation \[GJ23\] to avoid spending linear time in the array size to initialise its cells.
