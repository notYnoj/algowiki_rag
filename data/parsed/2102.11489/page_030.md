Specifically, we rely on a lossy loose compactor to extract the `blue` elements; and rely on an \(\epsilon'\)-near-sorter to extract the `red` elements for some sufficiently small constant \(\epsilon'\in(0,1)\). At this moment, the problem boils down to swapping almost all `blue` elements in the extracted array with a distinct, paired `red` element, and reverse routing the result back to the original array. We can accomplish this by recursing on the extracted array. The recursion stops when the extracted array’s size becomes _n/_`poly`log_n_ for some appropriate choice of \(\mathsf{poly}\mathrm{log}(\cdot)\).

We defer a formal description of the scheme and the parameters to the subsequent technical sections. This bootstrapping step incurs the following blowup in parameters:

• Let \(\alpha:=1/\mathsf{poly}\mathrm{log}n\) be the loss-factor of the \(\alpha\)-lossy loose compactor, then the resulting approximate splitter has the approximation factor \(8\alpha\).<tbc>

• Suppose that the 1/`poly`log(_n_)-lossy loose compactor has _B_<sub>lc</sub>(_n_) number of generalized boolean gates, and _S_<sub>lc</sub>(_n_) number of _w_-selector gates, and has _D_<sub>lc</sub>(_n_) depth, then the resulting approximate splitter has \(C_1\cdot B_\mathrm{lc}(n)\) generalized boolean gates, \(C_2\cdot S_\mathrm{lc}(n)\) number of _w_-selector gates, and \(C_3\mathrm{loglog}n\cdot D_\mathrm{lc}(n)\) depth, where _C_<sub>1</sub>_,C_<sub>2</sub>_,C_<sub>3</sub>_\>_2 are appropriately large constants.

**Lossy loose compactor from approximate splitter.** We want to construct a more efficient lossy loose compactor given an approximate splitter. Let _f(n)\<_log_n_ be some function on _n_, and let _C_<sub>sp</sub>_\>_1 be some appropriate constant. Suppose that we have an \(\alpha\)-approximate splitter that costs \(C_\mathrm{sp}\cdot n\cdot f(n)\) generalized boolean gates, \(C_\mathrm{sp}\cdot n\) number of _w_-selector gates, and _D_<sub>sp</sub>(_n_) depth. We can construct a lossy loose compactor as follows:

1. Divide the input array into _f(n_)-sized chunks. We say that a chunk is _sparse_ if there are at most _f(n)/_32 real elements in it; otherwise it is called _dense_. Since the input is promised to be 1/128-sparse, we will later prove that at least 3/4 fraction of the chunks are sparse.<tbc>

2. Call an \((\alpha,1/4)\)-approximate splitter to move almost all dense chunks to the front and almost all sparse chunks to the end. Here the approximate splitter works on _n/f(n_) elements each of bit-width \(f(n)\cdot w\).<tbc>

3. Apply an \((\alpha,1/32)\)-approximate splitter to the trailing \(\left[(\frac{3}{4}-\frac{1}{64})\cdot\frac{n}{f(n)}\right]\) chunks to compress each of these chunks to a length of \(\left[\frac{3f(n)}{64}\right]\), losing few elements in the process. The first \(\left[(\frac{1}{4}+\frac{1}{64})\cdot\frac{n}{f(n)}\right]\) chunks are unchanged. Output the resulting array.

The resulting lossy loose compactor has a lossy factor of \(1.74\alpha\); moreover, it costs at most \(2.1\cdot C_\mathrm{sp}\cdot n\cdot f(f(n))\) generalized boolean gates, at most \(2.1\cdot C_\mathrm{sp}\cdot n\) number of _w_-selector gates, and has depth 2.1_D_<sub>sp</sub>(_n_). Note that the total number of generalized boolean gates reduces quite significantly in this step but the total number of _w_-selector gates and the depth increase by a constant factor.

**Repeated bootstrapping.** We repeatedly perform the above bootstrapping. Henceforth going from lossy loose compactor to approximate splitter, and then back to a lossy loose compactor is called one step in our bootstrapping. After _d_:=log(log<sup>∗</sup>_n_-log<sup>∗</sup>_w_) steps of bootstrapping, the cost incurred by generalized boolean gates and _w_-selector gates will be balanced.
