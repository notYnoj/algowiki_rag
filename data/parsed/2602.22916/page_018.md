<tbc>case) is a unit-weight (_v_’s original weight) if _v_ does not appear in another face that is contained in _S_, otherwise, _v_ is assigned an input of zero. This is done to not overcount _v_. In our case, the input of a vertex _v_ is simply the weight that _v_ (originally) chose to contribute to _f_ (either _v_’s original weight or zero), that is, _v_ does not even have to check if it appears in another face enclosed by _S_ or not, because our assignment of faces does not suffer from overcounting. We note that there is a very subtle point, where the endpoints of the artificial edge _e_, that previously chose to transfer their weights to _f_, can now choose to transfer their weight either to _f<sub>in</sub>_ or to _f<sub>out</sub>_, either choice is fine (as shown in Lemma 5).

## A.2 Proof of Theorem 3 (Generalization to Multiple Subgraphs)

**Theorem 3.** _Let_ \(\{G_i\}_{i=1}^k\) _be a partition of G into vertex-disjoint connected subgraphs, and_ \(\{T_i\}_{i=1}^k\) _be spanning trees of G<sub>i</sub>s. In addition let_ \(\{w_i(\cdot)\}_{i=1}^k\) _be_ 1/12_-proper weight assignments to G<sub>i</sub>s’ vertices. Then, there is a deterministic_ \(\tilde{O}(D)\)_-round distributed algorithm that for each G<sub>i</sub> finds a_ 3/4_-balanced path separator P<sub>i</sub> w.r.t._ \(w_i(\cdot)\) _of_ \(O(\mathrm{depth}(T_i))\) _vertices. In addition,_ \(P_i\cup\{e\}\) _is a fundamental cycle of T<sub>i</sub>, where e_=(_u,v_) _and u,v are the endpoints of P. In case_ \(e\notin G_i\)_, then u,v learn the ID of each other, and a local ordering (embedding) of e that preserves planarity._

First, we give a brief overview why this generalization is possible. The first issue that needs to be resolved is that the algorithm needs to compute part-wise aggregations inside each _G<sub>i</sub>_. I.e., there is a given partition in each _G<sub>i</sub>_ that we want to compute part-wise aggregations with respect to, and in all _G<sub>i</sub>s_ simultaneously. However, is not hard to see that a collection of partitions of _G<sub>i</sub>s_ imply a partition of _G_. Thus, we can use Lemma 7 to compute aggregate operators. The second issue is that we cannot perform computations in the dual graph _G_<sup>∗</sup> straightforwardly because it is not the communication graph. However, a simple trick of [9] allows us to construct shortcuts for the faces of each _G<sub>i</sub>_, which are the nodes of \(G_i^*\). This allows to compute aggregate operators over faces of _G<sub>i</sub>_, and to compute subtree sums on dual trees \(T_i^*\).

_Proof._ We concretely describe how one can generalize Theorem 1 (the implementation of Algorithm 1) to work in all subgraphs _G<sub>i</sub>_, simultaneously, deterministically, and in \(\tilde{O}(D)\) rounds. While phrasing the algorithm in terms of part-wise aggregations gets us half way through, we still have to clarify some details. We break this into two cases, the first concerns computations on primal graphs, and the second on dual graphs.

**Computations on** _G<sub>i</sub>_**s.** This case is easy, we simply use the fact that with low-congestion shortcuts, we can implement an aggregation based algorithm on all _G<sub>i</sub>_ simultaneously, within the same round complexity of \(\tilde{O}(D)\) rounds (Lemma 7). However, the issue is that we actually want to compute part- wise aggregations inside each _G<sub>i</sub>_, that is, for each _G<sub>i</sub>_, we are given a partition _G_<sub>_i,_1</sub>_,G_<sub>_i,_2</sub>_,...,G_<sub>_i,k<sub>i</sub>_</sub> into vertex-disjoint connected subgraphs, and we want to solve a part-wise aggregation task over the parti tions \(\{G_{i,j}\}_{j=1}^{k_i}\) of all graphs _G<sub>i</sub>_ simultaneously. Nevertheless, this issue is well studied in the literature (e.g. [9, 10, 18]). In particular, one can think of the collection of second layer partitions as one partition \(\{G_{i,j}:i\in[k],j\in[k_i]\}\) of _G_ and straightforwardly construct shortcuts on it. This results with the desired \(\tilde{O}(D)\) rounds to compute an aggregate operator in every _G<sub>i,j</sub>_ (for all _i,j_). This is possible because each vertex _v_ of _G_ knows in which _G<sub>i</sub>_ it is contained, and _v_ knows in which part _G<sub>i,j</sub>_ it is contained. Thus, the partition is (distributively) known to _G_’s vertices, so low-congestion shortcuts can be constructed and part-wise aggregations can be computed (as in Lemma 7). Note, it may be the case that different vertices in different parts are in different stages of the algorithm, the issue in this is that some vertices may want to change the partition and construct shortcuts again, while other vertices are not in that stage yet. However, this can be easily solved by scheduling the update of partitions and reconstruction of shortcuts to start at specific rounds that are given by the algorithm. E.g. divide the time into intervals of _t=D_log_<sup>c</sup>n_ (for some constant _c_ of the algorithm) rounds, such that the partitions and shortcuts begin to reconstruct at the beginning of each interval. Then, aggregations are computed in the remaining time in the interval.
