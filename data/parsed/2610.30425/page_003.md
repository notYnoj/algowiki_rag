## 2 Related Work

### 2.1 Learned Sparse Embeddings

Sparse vector search is a foundational problem in information retrieval dating back to early foundational work on bag-of-words and term frequency representations of text [32]. However, traditional sparse lexical vectors are fundamentally limited in that they can only match queries to documents with exact keyword overlaps. _Learned_ sparse representations were conceived to address this shortcoming by utilizing neural networks to learn high-dimensional representations of vectors with a small number of nonzero components such that each component represents a generalized concept as opposed to a fixed word. Following the revolution in transformer- based representation learning, a number of works have studied how to train or fine tune learned sparse representations [2, 10- 12, 23, 24, 35].

One of the most influential families of learned sparse embeddings models is SPLADE [16, 18, 20, 21] which established learned sparse retrieval as a state-of-the-art technique for first-stage text retrieval. Recently, Formal [15] introduced SPARSEUP, a next-generation learned sparse embedding model that achieves improved retrieval quality over SPLADE and, to our knowledge, currently constitutes the best-in-class sparse embedding model for first-stage retrieval. Furthermore, another very recent line of work has studied the notion of _inference-free_ learned sparse embeddings which replace the query encoder model with a learned lookup table [28, 33].

### 2.2 Algorithms for Learned Sparse Retrieval

In addition to training models for encoding effective learned sparse embeddings, the retrieval community has also proposed numerous techniques for efficiently searching over these representations. A key finding in early work within this area is that learned sparse representations generate term distributions that differ considerably from the Zipfian nature of bag-of-words text representations, rendering traditional inverted indexes designed for text matching as inefficient [4, 25].

Several of the early specialized indexes for learned sparse retrieval involved graph-based search. The Neurips 2023 Big ANN benchmarking competition [34] included a dedicated learned sparse<tbc>

<tbc>retrieval track where the winning solutions, PyANNS and GrassRMA, utilized graph-based vector search, a dominant approach for dense vector retrieval [1], for learned sparse similarity search. Both PyANNS and GrassRMA utilize the HNSW graph index [26] with additional low-level optimizations, such as integer quantization of values and graph reordering [9], to improve performance. Notably, these methods do not seek to infuse the structural properties of inverted indexes into graph-based search, which, at a methodological level, differentiates GRIP.

These graph-based methods subsequently lost their standing as the state-of-the-art indexing solution for LSR following the introduction of Seismic [5] which achieved substantial efficiency improvements over PyANNS and GrassRMA using an inverted index tailored to the idiosyncrasies of learned sparse embeddings. Seismic has since been further improved in a number of follow-on works [6, 7, 29]. In addition to Seismic, several other systems have proposed efficient inverted indexes for LSR including Block-Max Pruning (BMP) [27], Dynamic Superblock Pruning (DSP) [8], and SINDI [22] that each seek to accelerate the posting list traversal component of inverted index-based search. The latest version of Seismic, described in the work of [29], includes further performance optimizations that achieve significant search quality-efficiency improvements over both other inverted index designs for LSR and graph-based approaches and, to our knowledge, represents the current state-of-the-art system for LSR. Thus, we treat this latest version of Seismic as our primary baseline when comparing with our proposed GRIP system.

## 3 Methodology

We now present the algorithmic details behind GRIP. As in prior work on graph-based search indexes, GRIP consists of an _offline_ index build phase and an _online_ search phase. Algorithm 1 and Algorithm 2 together describe the offline phase where we build a data structure of term-seeded entry points and construct the graph for traversal via our sparse PiPNN algorithm, respectively. Algorithm 3 then describes the online search procedure which follows the standard paradigm of graph-based search for ANN via beam search with two modifications: (i) we initialize the graph search with up to \(T\cdot L\) nodes, the _L_ highest-weighted documents (from the precomputed term seed lists) for each of the _T_ highest- impact query terms, and (ii) we perform the traversal using top-_R_ sketched sparse vectors and re-score the final top-_k_ results with the full embeddings.
