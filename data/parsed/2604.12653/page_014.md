## 5.5 The access operation

Recall that a leader is an active node in the main tree with an inactive parent. We perform access in two steps. First, we ignore the index trees and only update the main tree. We deactivate a bunch of nodes, which changes the set of leaders. Second, we bulk delete the destroyed leaders from the index trees, and bulk insert the newly created leaders into the index trees. This approach saves a bunch of time updating subtree minima in the index trees.

To implement access(_i_), first deactivate all non-leaf nodes on the root-to-leaf path of leaf _i_. Then, while there are consecutive leaders _u,v_ with \(\text{height}(u)-\text{height}(v)\ge 3\), deactivate _u_ and the right child of _u_. Similarly, whenever \(\text{height}(v)-\text{height}(u)\ge 3\), deactivate _v_ and the left child of _v_. Finally, erase all destroyed leaders from the index trees, and insert all newly created leaders into the index trees. Inserting or deleting leaders one-by-one would be too slow. Instead, for every _i_=0,1_,..._, we build a linked list _N<sub>i</sub>_ on all newly created leaders of height \((2\cdot 2^i,4\cdot 2^i]\) in left-to-right order, or height \[0,4\] for _i_=0. Then, for each affected index tree _L<sub>i</sub>_, we bulk delete the destroyed leaders from _L<sub>i</sub>_, and bulk insert _N<sub>i</sub>_ into _L<sub>i</sub>_. Note that, except for leaders of height \[0,2\] in _L_<sub>0</sub>, all newly created leaders are unpromoted (invariant (8)).

We now analyze this implementation of access(_i_):

**Lemma 16.** _At any point in time during and after the_ access _operation, the set of newly created leaders is_ contiguous_, that is, it forms a contiguous subsequence of all leaders in the left-to-right order._

_Proof._ Let _w_ be the leader of leaf _i_ before the access operation. First, we deactivate all non-leaf nodes on the path from _w_ to _i_. The newly created leaders are precisely the subset of leaders that lie in the subtree of _w_. Hence, they are contiguous. After that, we always find two consecutive leaders _u,v_ with \(|\text{height}(u)-\text{height}(v)|\ge 3\) and deactivate one of them, say _u_. Note that, since invariant (3) held before the access operation, at least one of _u,v_ has to be a newly created leader. Deactivating _u_ replaces it with two newly created leaders, so the set of newly created leaders remains contiguous.

**Lemma 17.** _At any point in time during and after the_ access(_i_) _operation, the heights of newly created leaders to the left of leaf i are non-increasing, and the heights of newly created leaders to the right of leaf i are non-decreasing. Moreover, at most two consecutive newly created leaders have the same height._

_Proof._ This is true after we deactivate all non-leaf nodes on the root-to-leaf path to node _i_. We show that Lemma 17 is maintained as we deactivate more nodes. Let _t,u,v_ be consecutive leaders with \(\text{height}(u)-\text{height}(v)\ge 3\). By assumption, Lemma 17 holds before we deactivate _u_. Thus, _t_ is either an old leader, or \(\text{height}(t)\ge\text{height}(u)\); and leaf _i_ lies weakly to the right of _v_. We deactivate _u_ and its right child. This replaces _u_ with three new leaders _u_<sub>1</sub>_,u_<sub>2</sub>_,u_<sub>3</sub> with height(_u_<sub>1</sub>)=height(_u_)-1 and height(_u_<sub>2</sub>)=height(_u_<sub>3</sub>)=height(_u_)-2. Thus, \(\text{height}(u_1)>\text{height}(u_2)\ge\text{height}(u_3)>\text{height}(v)\). And, _t_ is either an old leader, or height(_t)\>_height(_u_<sub>1</sub>). Moreover, among _t,u_<sub>1</sub>_,u_<sub>2</sub>_,u_<sub>3</sub>_,v_, only _u_<sub>2</sub> and _u_<sub>3</sub> can be new leaders of the same height. This shows that Lemma 17 still holds after the deactivations, so Lemma 17 is maintained until the end.
