<tbc>item with value \(\infty\). Finally, we return _x_. Observe that, at any point in time, the non-dummy items at the leaves are precisely the items that have not been extracted. Thus, the subtree minimum of the root of _T_ is the minimum of all these items, and this is a correct implementation of insert and extractMin.

As for the running time, the insert operation only calls addLeaf, which takes amortized _O_(1) time. To analyze the extractMin operation, we first observe that an item _x_ always gets stored in the leaf _i=a(x_). Moreover, the only calls to access we perform are a single call in every extractMin operation. Thus, after extracting the item _x_, we have _s(i_)=_b(x_). Consider now a call to extractMin that returns an item _x_ stored at a leaf _i_. Recall that the unified bound is \(U:=1+min_{y:b(y)<b(x)}\big(log|a(x)-a(y)|+log(b(x)-b(y))\big)\). Let _y_<sub>0</sub> be the value of _y_ that achieves the minimum and let _j_<sub>0</sub> be the index of the leaf that used to store _y_<sub>0</sub> before it was extracted. Since _b(y_<sub>0</sub>)_\<b(x_), the item _y_<sub>0</sub> was extracted before _x_. Thus, at this moment, we have _s(j_<sub>0</sub>)=_b(y_<sub>0</sub>). This implies

\(d(i)\le 1+log(1+|i-j_0|)+log(1+t-s(j_0))\)<br>
\(=1+log(1+|a(x)-a(y_0)|)+log(1+b(x)-b(y_0))\in O(U).\)

Hence, the amortized running time of access during the extractMin operation is indeed bounded by the unified bound. After running access(_i_), we have \(d(i)\in O(1)\), so the amortized running time of \(\text{changeKey}(i,\infty)\) is _O_(1). This shows that Theorem 12 implies Theorem 2. In the remainder of this section, we will prove Theorem 12.

## 5.1 Overview

At a high level, our data structure consists of two parts. First, the _main tree_: a complete binary tree with \(\Theta(n)\) leaves, ordered by index. Some nodes in this tree are _leaders_, where every leaf _i_ lies in the subtree of exactly one leader. We call this leader the _leader of leaf i_. Second, the _index trees_: we store the leaders in _O_(loglog_n_) balanced binary search trees of doubly exponential sizes. Each index tree is ordered by the left-to-right order of the leaders in the main tree. From the main tree and the index trees, we obtain a single tree, as required by Theorem 12, as follows: connect the roots of the index trees from big to small, and attach to each leader node in the index tree its subtree in the main tree. This yields some nodes with three children, but we can subdivide these nodes to get a binary tree. (This increases the depth of each leaf by at most a factor 2.)

In Theorem 12, leaf _i_ should have depth _O(d(i_)). Thus, in our construction, for any leaf _i_ with leader _v_, both the height of the subtree of _v_ in the main tree, and the height of the index tree that contains _v_ should be bounded by _O(d(i_)). We will implement the access(_i_) operation by moving the leaders down in the main tree, with the goal that leaf _i_ ends up at depth _O_(1). Our carefully chosen invariants then guarantee that nearby leaves _j_ also have depth _O(d(j_)). We implement an additional operation cleanup that moves the leaders up in the main tree, with the goal of reducing the size of the index trees. We invoke cleanup() after every addLeaf or access operation. Finally, it is easy to implement changeKey: since the values of items have no effect on the shape of our structure, we just update all subtree minima on the root-to-leaf path.

The main difficulty is maintaining the subtree minima in the index trees as we create and destroy leaders: while there are balanced binary trees with _O_(1) insertion or deletion after lookup, updating the subtree minima will take time linear in the height of the index tree. To deal with this, we use a charging argument where we insert log_S_ consecutive leaders into an index tree at once, where _S_ is the size of the index tree. Then, updating the subtree minima only takes _O_(1) time per leader inserted.
