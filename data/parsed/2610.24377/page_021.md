• no (non-catalytic) 1-output-pass algorithm can output such a _y_ using _n_<sup>_o_(1)</sup> space and \(n^{2-\Omega(1)}\) time.

_Proof._ Consider the relation \(R=\{(L,(L',L''))|L'\oplus L''=\mathsf{SORTED}(L)\}\). That is, given a list _L_, we want to output a pair of lists whose bitwise-XOR is equal to _L_ in sorted order. Observe that outputting such an \((L',L'')\) in the transducer model is equivalent to outputting the sorted list in the 2-output-pass model. So, this is implied by our above results. \(\blacksquare\)

## 5.2 Separating 1-pass and 2-pass catalytic time-and-space-bounded complexity

Given that the _k_-pass XOR and 1-pass XOR models are equivalent for constant _k_ (up to constant factors in time and space) without dirty space, one might ask whether they are similarly equivalent for catalytic algorithms. We show that this is unconditionally false: while catalytic algorithms can quickly sort in the 2-pass XOR model, they cannot do so in only a single pass.

**Theorem 5.4.** For any catalytic transducer that takes in a length-_n_ list of log(_n_)-bit integers and outputs the sorted list, we must have \(ST\unknown\Omega(n^2)\), where _S_ and _T_ are the clean space and runtime used by the algorithm, respectively.

_Proof._ The proof we give directly follows Beame’s time-space tradeoff lower bound in the case with no catalytic space \[Bea91\].

Recall the notion of a _catalytic branching program_ operating over a list \[GKM15\]. A standard branching program is a directed acyclic graph, where each node is labeled with an index of the list to read, and has an outgoing edge corresponding to each possible value that could be read at each index. Some nodes are also marked with one or more _output values_. Given an input list, one can produce an output list by starting at a designated "input node", querying the input list in the specified place, following the corresponding out-edge, outputting any output values specified by the new node, and repeating. In a _catalytic_ branching program, there are instead _several_ nodes designated as "start nodes", each with a corresponding "end node". We require that the output is always correct regardless of which of these start nodes the program begins at, and that the program always ends at the end node corresponding to the start node where it began. Say that a branching program is "layered" if nodes can be partitioned into layers such that each edge connects nodes in adjacent layers. Let the _length_ of a branching program be the number of layers, and the _amortized size_ be the number of nodes divided by the number of start nodes.

Observe that, if we have a time-_T_, clean-space _S_ catalytic transducer for a problem, we immediately get a length-_O(T_), amortized width-2<sup>_O(S_)</sup> catalytic branching program for that problem. (To see this, let each possible state of the Turing machine correspond to a node of the branching program, let the edges correspond to the transitions the machine would perform, and let the start and end nodes correspond to the machine in the start and end states with the clean space empty. If _w_, _c_, and _f_ are the number of bits of workspace, catalytic space, and finite Turing machine control respectively used by the machine, then this catalytic branching program will have 2<sup>_w+c+f_</sup> nodes and 2_<sup>c</sup>_ start nodes.) So, it suffices to show that sorting does not have a catalytic branching program of amortized size 2_<sup>S</sup>_ and length _T_ for any \(ST\unknown o(n^2)\).

In fact, we show that the _unique elements_ problem, of outputting (in an arbitrary order) all of the elements of a list that appear exactly once, does not have such a catalytic branching program. As a time-_T_, clean-space _S_ transducer for sorting can easily be converted into a time-_O(T_), clean-space _O(S_) transducer for unique elements, this gives the desired result.

Fix some catalytic branching program with _T_ layers, _x_ start vertices, and \(x\cdot 2^S\) total vertices. For a node _v_ in the branching program, and an input list _L_, we will say (_v,L_) is _good_ if, when starting from _v_ and taking _n/_2 branching program steps, the program outputs at least _n_<sup>2</sup>/400_T_ distinct values in \[_n_\], each of which appears at most once in _L_.
