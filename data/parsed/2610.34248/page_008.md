For graph access, this causes no address repetition: each layer stores its own graph with independently reshuffled addresses, so expanding the same logical node in different layers always reads unrelated locations. For vector access, however, standard HNSW implementations keep all vectors in one global table for space and cache efficiency, so re-evaluating a node across layers hits the same physical address. To avoid this, we assign each layer its own independently reshuffled vector table of size \(N_\ell\). Notably, within a single layer, the graph and vector tables are reshuffled independently, so a node’s graph and vector entries occupy unrelated physical addresses, avoiding graph-to-vector transitions by reusing an address. With this per-layer duplication and independent reshuffling, both graph and vector access become fully non-repetitive.

### 4.4 Put It All Together

We now integrate the oblivious control flow, data structures, and access patterns into a complete single query HNSW protocol under MPC. Here, we first describe how the per-layer data is represented and secret-shared. At each layer \(\ell\), the data owner provides two tables: a graph table \(\mathcal{G}_\ell\) containing neighbor lists as the HNSW index and a vector table \(\mathcal{D}_\ell\) containing the node vectors. Both tables are padded with _TM+T+ef_ dummies, where _TM_ is for visited check, while _T+ef_ is for initialization of _C_ and _W_. After padding, MPC parties secret-share and jointly reshuffle the tables offline. Each graph table entry stores _M_ neighbors’ vector-table addresses, \(\mathcal{G}_\ell[i]=(\unknown n_{i,0}\unknown,\dots,\unknown n_{i,M-1}\unknown)\), where \(\mathcal{D}_\ell[n_{i,j}]\) would return the _j_-th neighbor’s vector and auxiliary information. Each vector table entry is \(\mathcal{D}_\ell[j]=(\unknown\vec{v}_j\unknown,\unknown a_j\unknown,\unknown b_j\unknown,\unknown m_j\unknown)\), where \(\vec{v}_j\) is the node’s vector; _a<sub>j</sub>_ is the graph table address of the nodes; _b<sub>j</sub>_ is the address of the same vector in \(\mathcal{D}_{\ell-1}\) (used during layer transition); and \(m_j\in\{0,1\}\) is the dummy entry flag. We collect all dummy vector addresses in a pool \(\text{DUM}_\ell=(\unknown d_0\unknown,\dots,\unknown d_{MT+T+ef-1}\unknown)\).

During the search, MPC parties jointly maintain three fixed- size arrays at each layer: \(V=\{\unknown a_i\unknown\}_{i=0}^{MT}\), \(C=((\unknown c_i\unknown,\unknown d_i\unknown))_{i=0}^{T-1}\), and \(W=((\unknown w_i\unknown,\unknown b_i\unknown,\unknown\delta_i\unknown))_{i=0}^{ef-1}\). Here _V_ stores the vector-table addresses _a<sub>i</sub>_ of visited nodes; _C_ stores the graph-table addresses _c<sub>i</sub>_ and distances _d<sub>i</sub>_ of candidate nodes; _W_ stores the vector-table address _w<sub>i</sub>_, the lower-layer vector address _b<sub>i</sub>_, and the distance \(\delta_i\) of the current top-_ef_ results nodes.

With the oblivious data structures in place, Algorithm 2 specifies the per-layer search, which runs a fixed number of iterations and updates _V_ , _C_, and _W_ obliviously. The full single-query protocol (Algorithm 3) applies this layer search from the top layer to the base. At the base layer, _W_<sub>0</sub> stores only vector-table addresses for efficient oblivious sorting; the actual vectors are fetched from an auxiliary reshuffled table D<sub>-1</sub>. Since the base layer may place dummy addresses among the top-_k_ when _k_ is large, D<sub>-1</sub> is padded with _MT+T+ef_ dummy entries containing application-safe vectors so that dummy outputs remain indistinguishable from real ones.
