## 2.1 Warm-Up: A Simple Improvement

Our simple algorithm relies on two key observations: (1) MSSP can be computed efficiently on graphs with small diameter, and (2) MSSP can be computed efficiently when each layer of the shortest path tree is small. On graphs with diameter at most _D_, we can compute MSSP by taking the adjacency matrix and computing the matrix product _A_\[_S,V_\]_A<sup>d</sup>_ for every \(d\le D\) in _O(D_T<sub>MUL</sub>(|_S_<sub>in</sub>|_,n,n_)) time by iteratively multiplying the adjacency matrix _A_ on the right. In graphs where each layer of the shortest path tree (i.e. \(\{v\text{s.t.}\text{dist}(s,v)=\ell\}\)) has at most _T_ vertices, executing SSSP for a single vertex only requires _O(nT_) time (in contrast to _O(n_<sup>2</sup>) in general). This leads us to the following algorithm. Let _L(s,r_):={_v_ s.t. dist(_s,v_)=_r_} be the _r_-th layer of the shortest path tree from source _s_.

\(\text{1. Let}T\text{be a parameter to be set later. (We will set}T\leftarrow\sqrt{\mathsf{T}_\text{MUL}(|S_\text{in}|,n,n)/|S_\text{in}|}\text{). 2. Initialize}L(s,0)=\{s\}\text{for all}s\text{. Set all}s\text{to active. (Execute BFS from all}s\text{in parallel.) 3. While not all distances computed: (a) If some source}s\text{is active: (Small Layer Case) i. Attempt to compute}L(s,\text{level}(s)+1)\text{by relaxing all edges from}L(s,\text{level}(s)\text{). ii. If}|L(s,\text{level}(s)+1)|\le T\text{, compute}L(s,\text{level}(s)+1)\text{and increment level}(s)\text{. iii. If}|L(s,\text{level}(s)+1)|>T\text{, set}s\text{as inactive. (b) If all sources}s\text{are inactive: (Large Layer Case) i. Compute}L(s,\text{level}(s)+1)\text{simultaneously for all}s\text{by computing}AB\text{where:}A[s,u]=\unknown\left[\text{dist}(s,u)=\text{level}(s)\right],B[u,v]=\unknown\left[(u,v)\in E\right]\text{ii. Increment level}(s)\text{for all}s\text{and set all sources}s\text{to active.}\)

Our algorithm computes BFS in parallel from every source. For each source _s_, we separately analyze the time required to compute large layers (_\>T_) and small layers (\(\le T\)) of the shortest path tree. For small layers (layers _r_ where \(\mathrm{max}(|L(s,r-1)|,|L(s,r)|,|L(s,r+1)|)\le T\)) to extend layer _r_ to _r_+1 requires time _O_(|_L(s,r_)|_T_), which overall requires _O_(|_S_<sub>in</sub>|_nT_). For large layers, we note that each source _s_ can only have _O(n/T_) large layers, and therefore become inactive at most _O(n/T_) times. Since we only compute the matrix product when all sources are inactive, all matrix products require \(O\left(\frac{n}{T}\mathsf{T}_\text{MUL}(|S_\text{in}|,n,n)\right)\) time. Balancing terms, we set \(T\leftarrow\sqrt{\mathsf{T}_\text{MUL}(|S_\text{in}|,n,n)/|S_\text{in}|}\) and obtain a running time of \(O\left(n\sqrt{|S_\text{in}|\mathsf{T}_\text{MUL}(|S_\text{in}|,n,n)}\right)\). For example, for \(|S_\text{in}|\le n^{0.32}\), T<sub>MUL</sub>(|_S_<sub>in</sub>|_,n,n_)=_n_<sup>2+_o_(1)</sup> \[ADV<sup>+</sup>25\], which yields a \(\sqrt{|S_\text{in}|}n^{2+o(1)}\) running time, improving upon \(O\left(|S_\text{in}|n^2\right)\).

## 2.2 Optimal Multiple-Source Shortest Paths

The above algorithm suggests a potential more generic approach: when we try to grow the BFS tree of some source by one layer, we could wait until many sources need to do so, and group the computation into a matrix multiplication. To further improve the running time, it is natural to use more thresholds, instead of a single threshold _T_. Now when we group multiple sources together, we need a better bound on the size of the union of the corresponding layers. In order to really take advantage of batch processing, we need these layers to have large overlaps - if all the layers are disjoint, then batch processing does not help at all. In the above simple improvement, we only perform batch processing for very large layers, and we simply used _n_ as the upper bound on the size of the union. For smaller layers, why wouldn’t layers of different sources be mostly disjoint (like random sets)? Hence, in order to proceed, we develop some structural insights of undirected unweighted graphs, in particular, a novel low diameter decomposition.
