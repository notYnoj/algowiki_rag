## 23:10 Simple in-place yet comparison-optimal Mergesort

For the new _in-place Mergesort_ the usual but non-_in-place_ merging routine is replaced with the new _in-place_ variant presented in Algorithm 5. It utilizes both prerequisites from Section 2 in the following way: The new _in-place_ merging takes an input array that is then subdivided by an index _i_ into two already sorted subsequences. These usually originate from the left and right _Mergesort_ after these recursions have been completed. In principle, this splitting point _i_ can be chosen arbitrarily, but for performance reasons, it should be close to the middle of the input array. Using the _co-ranking_ functionality from Section 2.2, we determine the corresponding _co-ranks j_ and _k_ for this _i_ in both subsequences. As already mentioned previously, this can be done in O(log_n_) time for a total of _n_ elements using only constant space. Once these _co-ranks_ are known, the array is then logically partitioned such that all array elements between these two indices are considered to form one consecutive middle array. This middle array is then rotated either by the resulting offset _k_ to the right or alternatively by _i-j_ to the left<sup>3</sup>. Utilizing the time- and space-optimal array rotation from Section 2.1, this can be achieved _in place_. Note that this array rotation essentially moves all "small" elements to the left of _i_ and all "large" elements to its right. More precisely, afterward, all elements left of _i_ precede _A[i_], and all elements right of _i_ succeed _A[i_-1]. In fact, this is guaranteed by the stable design of the _co-ranking_ functionality (see [12] for more details). Thus, the rotation does not need to care about stability anymore. Finally, we can recursively call this _in-place_ merging routine again on both array halves, which itself are already subdivided into two arrays at _j_ and _k_ respectively. As usual, this recursion stops whenever fewer than two elements are remaining. Algorithm 5 presents this new and recursive _in-place merge_ approach.

To facilitate better understanding, the entire _in-place Mergesort_ scheme is also illustrated in Figure 3.

<sup>3</sup> Since _i-j=k_ due to the invariant of the _co-ranking_ functionality, it does not matter if we rotate _k_ to the left or to the right. This might sound counter-intuitive at first, but because rotating _r_ to the left is equivalent to rotating _n-r_ to the right (see note 1), we get (_i-j_)+_k-k=i-j=k_.
