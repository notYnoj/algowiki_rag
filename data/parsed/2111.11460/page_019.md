First we apply the counting protocol for (_n,n_)-Counting to find the number of 1’s in each of the two partitions. Let the two counts be _i_ and _j_ and players _P<sub>i</sub>_ and _P<sub>j</sub>_ know the count each. But, player _P<sub>i</sub>_ does not know _j_ and player _P<sub>j</sub>_ does not know _i_. However, the player knows if it has the first or second count.

The protocol to compute the target function will consists of multiple phases where each phase is well defined. The number of phases will be a constant. Therefore any message from player _P<sub>a</sub>_ to _P<sub>b</sub>_ will consists of a phase number followed by the message. For the ease of presentation, we will omit phase number information from the message exchanged between players. Since the number of phases is a constant the asymptotic bound on the local complexity does not change if we omit phase number in the calculation.

We start with a protocol for computing a function that depends on only one of two variables, say _i_. Given the function and the input _i_, _P<sub>i</sub>_ computes the function by calculating the output \(x\in\{0,1,\dots,n\}\). _P<sub>i</sub>_ sends a message to _P<sub>x</sub>_, thus completing the computation.

We now establish protocol to determine if _i=j_, _i\>j_ or _i\<j_. It is trivial to see if _i=j_, since player _i_ has both counts. If \(i\neq j\), player _i_ initiates a protocol with two phases. Suppose _i\>_0. The first phase starts with _P<sub>i</sub>_ sending 0 to _P_<sub>_i_-1</sub>. Each player _P<sub>k</sub>_, upon receiving a bit 0 sends bit 0 to the player _P_<sub>_k_-1</sub> until it reaches either player _j_ or 0. We call this a 0-down sweep. We now consider the case where _P<sub>j</sub>_ receives 0. _P<sub>j</sub>_ will initiate the second phase by sending bit 1 to _P_<sub>_j_+1</sub>. Each player, upon receiving 1 sends 1 to _j_+1 which will ultimately reach _i_, 1-up sweep. Upon receiving 1, _P<sub>i</sub>_ knows that _i\>j_.

On the other hand, suppose _P_<sub>0</sub> receives 0 and \(j\neq 0\). _P_<sub>0</sub> initiates 0-up sweep which will terminate at _P<sub>i</sub>_. Upon receiving 1, _P<sub>i</sub>_ knows that _i\<j_.

_P<sub>i</sub>_ will inform _P_<sub>0</sub> through _P<sub>n</sub>_ the result by sending a bit _b_ (= 0 if _i\<j_ and 1 otherwise) to _P_<sub>0</sub>. Upon receiving _b_, _P_<sub>0</sub> will start a _b_-up sweep which ends with _P<sub>n</sub>_.

We now consider the modular arithmetic. The important operation is subtraction. We now present a protocol to compute (_i-j_). _P<sub>i</sub>_ knows that it has the first parameter and _P<sub>j</sub>_ knows that it has the second parameter. If \(i\ge j\) then _x=i-j_ else _x_=(_n_+1)-(_j-i_). Note that \(x\equiv(i-j)mod(n+1)\). At the end of the protocol, _P<sub>x</sub>_ knows it has \(x\equiv(i-j)mod(n+1)\).

We run the protocol to determine if \(i\ge j\) or not. If _i=j_ the _P<sub>i</sub>_, informs _P_<sub>0</sub> the answer, thus ending the computation. Now, suppose _i\>j_. Suppose _j\>_0, a new phase starts at _P_<sub>0</sub> which initiates a 0-up sweep which terminates at _P<sub>j</sub>_. During this sweep a special 0 is stored at each player _P_<sub>0</sub> through _P_<sub>_j_-1</sub>. Upon receiving a bit, either from _P_<sub>_j_-1</sub> or from _P<sub>i</sub>_ (happens when _j_=0), _P<sub>j</sub>_ initiates 1-up sweep which terminates at _P<sub>i</sub>_. During this sweep, the players _P<sub>j</sub>_ through _P_<sub>_i_-1</sub> store a special 1 each. Now _P<sub>i</sub>_ starts a 0-up sweep which terminates at _P<sub>n</sub>_. During this sweep, the players _P<sub>i</sub>_ through stores a special 0 each. Now, run the protocol to compute the number of special 1’s among players _P_<sub>0</sub> through _P<sub>n</sub>_. The result is (_i-j)mod(n_+1).

We now consider the case _i\<j_. We run three up sweeps. This time we store special 1’s at players _P_<sub>0</sub> through _P_<sub>_i_-1</sub> and _P<sub>j</sub>_ through _P<sub>n</sub>_ while storing special 0’s at _P<sub>i</sub>_ through _P_<sub>_j_-1</sub>. Counting the number of special 1’s among players _P_<sub>0</sub> through _P<sub>n</sub>_ results in (_i-j)mod(n_+1). This completes the computation of subtraction.

We now consider the computation of addition _i+j_. _P<sub>j</sub>_ computes -_j_ and sends a message to _P_<sub>_n_+1-_j_</sub>. Observe \(i+j\equiv i-(n+1-j)modn+1\).

Given _i_, _P<sub>i</sub>_ computes \(x\equiv i^2mod(n+1)\) and sends a message to _P<sub>x</sub>_, thus computing _i_<sup>2</sup>. Simple algebra shows that multiplication can be computed by following the computations of the equation \(4ij\equiv(i+j)^2-(i-j)^2mod(n+1)\). If _P<sub>y</sub>_ knows 4_ij_ then it can compute \(z\equiv ijmod(n+1)\) and sends a message to _P<sub>z</sub>_. All of the above operations can be computed even when _n_+1 is not a prime number.

When _n_+1 is a prime, inverse exists for every \(1\le i\le n\). Therefore, division can be computed by observing \(i/j\equiv ij^{-1}mod(n+1)\). The protocol for division is straightforward and works if _n_+1 is a prime.

Finally, we present a protocol to compute _i<sup>j</sup>mod(n_+1). There is primitive root _g_ modulo (_n_+1) such that for every \(1\le a\le n\) there is an integer \(a'(0\le a'<n)\) such that \(a\equiv g^{a^\prime} mod(n+1)\). All players are aware of the generator and so _P<sub>i</sub>_ finds _a_ such that \(i\equiv g^amod(n+1)\) and sends message to _P<sub>a</sub>_. Now _P<sub>a</sub>_ and _P<sub>j</sub>_ runs the multiplication (modulo _n_) protocol to compute \(b\equiv ajmodn\) which result in a message to _P<sub>b</sub>_. Finally _P<sub>b</sub>_ computes the result of the exponentiation \(c\equiv g^bmod(n+1)\) and sends a message to _P<sub>c</sub>_.
