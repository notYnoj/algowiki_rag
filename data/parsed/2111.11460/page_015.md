**Lemma 5.2.** _Suppose_ \(x\ge 3\) _is an integer. Assume two sets of x players with one input bit each, where each collection of x bits is interpreted as a binary integer. There exists a protocol with local complexity_ 2 _that computes the binary sum of these two numbers and stores the result in a third set of x_+1 _players, using an additional set of_ 2_x players to support the computation, leading a total of x+x_+(_x_+1)+2_x_=5_x_+1 _total players involved. Though the overall local complexity is_ 2_, the_ 2_x players involved in storing the two input numbers send_ 1 _bit each and receive none during the computation and x_+1 _players storing and the resultant sum send at most_ 1 _bit each during the computation._

_Proof._ Let _a<sub>x</sub>...a_<sub>3</sub>_a_<sub>2</sub>_a_<sub>1</sub> be bits defining the first number a _b<sub>x</sub>...b_<sub>3</sub>_b_<sub>2</sub>_b_<sub>1</sub> be the bits defining the second. Let _r_<sub>_x_+1</sub>_r<sub>x</sub>...r_<sub>3</sub>_r_<sub>2</sub>_r_<sub>1</sub> be the resulting sum. In the following, we use the notation _P<sub>a<sub>i</sub></sub>_, for a given labelled bit _a<sub>i</sub>_, to denote the players responsible for bit _a<sub>i</sub>_. In addition to these 3_x_+1 players, we will use 2_x_ additional players, which we label _P<sub>t<sub>i</sub></sub>_ and _P<sub>c<sub>i</sub></sub>_, for each \(1\le i\le x\).

We now describe the computation. For each \(1\le i\le x\), _P<sub>a<sub>i</sub></sub>_ and _P<sub>b<sub>i</sub></sub>_ send their bits to _P<sub>t<sub>i</sub></sub>_. Upon receiving two bits, each _P<sub>t<sub>i</sub></sub>_ computes the XOR of the two bits and sends the result to _P<sub>r<sub>i</sub></sub>_. This value represents a tentative sum of the relevant two bits. Each _P<sub>t<sub>i</sub></sub>_ also computes the AND of these two bits, encoding the tentative carry, and sends it to _P<sub>c<sub>i</sub></sub>_. For _P<sub>r<sub>i</sub></sub>_ to compute the final sum for this bit position, it also needs to know the relevant carry, which it can receive from _P_<sub>_c_<sub>_i_-1</sub></sub>. Similarly, for _P_<sub>_c_<sub>_i_-1</sub></sub> to know the full carry to send to _P<sub>r<sub>i</sub></sub>_, it needs to learn not just the carry bit from _P_<sub>_t_<sub>_i_-1</sub></sub>, but also any carry resulting from the sum computed by _P_<sub>_r_<sub>_i_-1</sub></sub>.

Let us pull together these pieces: For \(2\le i\le k\), each _P<sub>r<sub>i</sub></sub>_ and _P<sub>c<sub>i</sub></sub>_ computes and communicates the following after receiving two bits in any order. _P<sub>r<sub>i</sub></sub>_ computes XOR of the two received bits and stores it as the resultant sum bit. _P<sub>r<sub>i</sub></sub>_ computes AND of the two received bits and sends it to _P<sub>c<sub>i</sub></sub>_. _P<sub>c<sub>i</sub></sub>_ computes OR of the two bits and sends it to _P_<sub>_r_<sub>_i_+1</sub></sub>. _P_<sub>_r_<sub>_k_+1</sub></sub> stores the bit it received the most significant bit of the sum. We can bootstrap the relevant processes in position 1 to send the correct value on initialization (e.g., _P_<sub>_r_<sub>1</sub></sub> has no carry bits to receive). It is easy to verify that the resultant sum computation is correct and it meets the required communication bounds. □

We are now ready to describe a protocol that solves (_n,n/_10)-counting with local complexity of 2. This protocol will leverage the distributed adding strategy captured in the preceding lemma to effectively count 1 bits among the first _n/_10 positions in an efficient manner. The remaining (9/10)_n_ nodes will be used to implement the results, totalling, and carrying roles needed by this addition.

**Theorem 5.3.** _For every n and k, such that_ \(0\le k\le n/10\)_, there exists a protocol that solves_ (_n,k)-counting with a local communication complexity of_ 2.

_Proof._ Assume _m=_10_n_ and so we are computing number of \(1's\) in the first _n_ positions. As in our proof of (_n,n_)-counting result, we assume for now that _n_ is a power of 2. (The same technique that eliminates this assumption for the (_n,n_)-counting case applies here, but as before we omit for the sake of clarity.) The computation follows the main idea of the proof of Theorem 5.1. However, we will use an additional 9_n_ members to reduce the number of bits used in the 11-bit protocol to 2 bits.

We partition _m=_10_n_ players into 10 groups of _n_ members each. The goal is to count the number of 1’s in the first group. The input contained in the remaining 9 groups will be ignored and the players will be used to support the counting of 1’s in the first group.

The protocol is divided into six phases. In phase 1, the second group of _n_ players will receive information from first group in the following way. Partition the input bits of first group into collection of two positions at a time (say _a<sub>i</sub>,a_<sub>_i_+1</sub>) and perform a simple binary addition of the two bits for each n/2 collections and store the 2-bit output of the binary addition in the corresponding two positions (say _b<sub>i</sub>,b_<sub>_i_+1</sub>) in the second group. It is easy to see that this can be accomplished where both players (say _a<sub>i</sub>_ and _a_<sub>_i_+1</sub>, _i_ is odd) in the first group send one bit to each of the two players _b<sub>i</sub>_ and _b_<sub>_i_+1</sub>. The players in the second group receives two bits each but each player can still send 2 bits.
