_Proof._ We first argue that there must be at least one initiator. Assume for contradiction that for some input assignment, _b_<sub>1</sub>_,b_<sub>2</sub>_,...,b<sub>n</sub>_, there are no initiators. It follows that no players send or receive any bits. Because we assume P correctly computes \(f_k^n\), some player must output the correct answer without ever having received any bits. Let _P<sub>i</sub>_ be a player that outputs. If it outputs 1, meaning there is at least _k_ input bits set to 1 in our fixed assignment, it will do the same even when set all other input bits to 0--leading to an incorrect output. Symmetrically, if _P<sub>i</sub>_ outputs 0, it will do the same when we set all other input bits to 1--leading to an incorrect output. This contradicts the correctness of P.

Moving forward, therefore, we consider the case in which there are more than one initiator. Once we have established that there cannot be more than one initiator, we will show that this one initiator must be the same for all input assignments. Assume for contradiction that there exists some input assignment, _b_<sub>1</sub>_,b_<sub>2</sub>_,...,b<sub>n</sub>_ for which P has more than one initiator. Let _P<sub>i</sub>_ and _P<sub>j</sub>_ be two such initiators. Assume that the initialization code for _P<sub>i</sub>_ with input bit _b<sub>i</sub>_ has _P<sub>i</sub>_ send bit \(b'_i\) to player _P<sub>x</sub>_, and the initialization code for _P<sub>j</sub>_ with _b<sub>j</sub>_ has it send \(b'_j\) to _P<sub>y</sub>_. Using these observations on the behavior of _P<sub>i</sub>_ and _P<sub>j</sub>_ we will identify an input assignment, \(\hat{b}_1,\hat{b}_2,\dots,\hat{b}_n\) that we can leverage to identify a contradiction.

Fix \(\hat{b}_i=b_i\) and \(\hat{b}_j=b_j\). Fix \(\hat{b}_x=\hat{b}_y=1\). Fix input values for the remaining players such that the total number of 1 bits in the assignment is exactly _k_ (because we assume \(k\ge 4\), this is always possible).

Consider an execution of P with assignment \(\hat{b}_1,\hat{b}_2,\dots,\hat{b}_n\). Because this is an asynchronous systems an execution for a given input can depend on the scheduling of send and receive events. Assume a _round robin_ scheduler that proceeds in _rounds_ as follows: During the first round, it visits each player in order _P_<sub>1</sub>_,P_<sub>2</sub>, and so on, scheduling each player to complete its initialization transmission (if any). In each subsequent round, it visits each player in order, for each, scheduling the processing of bits transmitted in the previous round, and then completing any new transmissions these received bits generate. Call this execution \(\alpha\).

In this execution we can break up communication into what we call _chains_, which capture the causal relationship of sends and receives beginning with a given root player. For example, if we fix _P<sub>i</sub>_ as a root, and note that _P<sub>i</sub>_ sends a bit to _P<sub>x</sub>_, which then enables _P<sub>x</sub>_ to send a bit to some \(P_{x^\prime}\), and so on, we note that there is a chain rooted at _P<sub>i</sub>_ that begins \(P_i,P_x,P'_x,\dots\)

Moving on, we note that by construction: \(f_k^n(\hat{b}_1,\hat{b}_2,\dots,\hat{b}_n)=1\). It follows that at least one player must output 1 in \(\alpha\). Fix one such player _P<sub>z</sub>_ that outputs 1. We argue that _P<sub>z</sub>_ cannot be in both the chains rooted at _P<sub>x</sub>_ and _P<sub>y</sub>_. If this was the case, then at some point as we followed the chain from _P<sub>x</sub>_ to _P<sub>z</sub>_, and the chain from _P<sub>y</sub>_ to _P<sub>z</sub>_, some node _P_<sup>∗</sup> would have to be visited in both. This would require _P_<sup>∗</sup> to receive at last 2 bits which is not allowed in a protocol with a local complexity of 1

Without loss of generality, assume that _P<sub>z</sub>_ is not in the chain rooted at _P<sub>x</sub>_ (the other case is symmetric). Consider the execution \(\alpha_x\), in which: (1) the input bit to _P<sub>x</sub>_ is changed to 0; (2) we replace the round robin scheduler with one that first schedules the nodes in the communication chain from _P<sub>j</sub>_ to _P<sub>y</sub>_ and on to _P<sub>z</sub>_, in order, leading _P<sub>z</sub>_ to output. After this, we can revert to the round robin scheduler strategy to ensure all pending players get chances to take steps.

By construction, \(\alpha_x\) is indistinguishable from \(\alpha\) with respect to _P<sub>z</sub>_. Therefore, _P<sub>z</sub>_ will output the same value in \(\alpha_x\) as \(\alpha\). Because we flipped the input value of _P<sub>x</sub>_ in \(\alpha_x\), this output is wrong. This contradicts the assumption that P always correctly computes \(f_k^n\).

We have now established that every input assignment has exactly one initiator. We want to now show that this initiator is the _same_ for every assignment. To do so, assume for contradiction that assignment _I<sub>i</sub>_ has _P<sub>i</sub>_ as its single initiator, and assignment \(I_j\neq I_i\) has player \(P_j\neq P_i\) as its single initiator. Consider a third assignment _I<sub>i,j</sub>_ which is defined the same as _I<sub>i</sub>_ with the exception that player _P<sub>j</sub>_ is given the same bit as in _I<sub>j</sub>_. We have now identified an assignment with two initiators. We argued above, however, that every assignment has at most one initiator: a contradiction. □
