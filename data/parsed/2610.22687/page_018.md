Drivers can either be JAX-native drivers (e.g. Optimistix non-linear solvers [61] or Diffrax [60] for differential equations) or existing implementations in e.g. SciPy [62] (which are handled through Python callbacks which are therefore not compiled in the same graph and do not necessarily support the JAX transformations). Such drivers are handed their component subgraph, their required input data (e.g. initial guesses and tolerances), and the context (the boundary input variables of their component subgraph) -- they iterate (or integrate) the subgraph until their conditions are satisfied (nesting if required; gradient-based drivers may call the autodifferentiated program for a Jacobian).

Drivers known ahead of time (i.e. specifically tailored to their associated function) can either be absorbed within that function or be assigned from the start.

Gradient-based optimisation or solving is supported through JAX’s composable autodiff on the graph, satisfying requirement 4. Each functional node defining its vector-Jacobian product (VJP, for reverse mode) and Jacobian-vector product (JVP, for forward mode) is sufficient to yield an entirely differentiable graph. This includes the drivers over the conditions: they can define a custom VJP/JVP using implicit differentiation over their solve using e.g. adjoint methods in Lineax [63], non-linear implicit differentiation in Optimistix, or implicit differentiation over optimisation problems [64]. A VJP/JVP over the entire graph then automatically runs (nested) coupled adjoint or direct derivatives of the solves.

Non-native JAX functions can be wrapped using callbacks or e.g. in a more general manner [65] -- this does introduce some overhead compared to pure-JAX programs. However, if the functions are sufficiently expensive (more than a few milliseconds), this overhead is negligible. If derivatives are required, they should define a VJP or JVP, which is also possible using finite differences as fallbacks. These finite differences can then be used as well for the residuals with an implicit VJP (i.e. using the adjoint method where the partial Jacobian is obtained from finite differences). If models are wrapped in this way, JAX merely provides a chain rule to efficiently compose the VJP/JVPs for differentiability.

Jacobian-colouring techniques are currently not implemented, but the dependency graph defines precisely the Jacobian sparsity pattern and could be exploited. Alternatively, Jacobian-free Newton–Krylov solvers could be used, which only require the aforementioned JVP/VJP.

The current execution layer also does not exploit the model-level parallelism implicit in the graph (i.e. models not depending on each other’s output that could be executed in parallel). This does not map well to the JAX-parallelism model, but could later be implemented using e.g. callbacks or multi-device execution.
