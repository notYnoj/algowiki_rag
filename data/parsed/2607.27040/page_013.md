## 3 Sorting In-Place

Finally, we demonstrate how the buffer memory and bit vector used in Section 2 are carved out directly from the input array, following the in-place conversion technique of [2].

**The bit vector** is first created by using heapselect to isolate the smallest and largest \(v=\lceil n/lg^2n\rceil\) elements into the blocks _L=l_<sub>1</sub>_...l<sub>v</sub>_ and _R=r_<sub>1</sub>_...r<sub>v</sub>_ respectively, resulting in the configuration \(L\mathcal{A}'R\). Because _L_ and _R_ contain the smallest and largest elements in A, sorting \(\mathcal{A}'\) would sort A. This process requires _O(n+v_lg_n_)=_O(n_) time. The _i_th bit is encoded by the pair (_l<sub>i</sub>,r<sub>i</sub>_): if _l<sub>i</sub>\<r<sub>i</sub>_ the bit is 0, otherwise it is 1. The operation write(_i_) simply swaps _l<sub>i</sub>_ and _r<sub>i</sub>_. For this encoding to be valid, no pair can be equal, thus we test _l<sub>v</sub>\<r_<sub>1</sub>: if this is true the encoding is valid, otherwise the region \(\mathcal{A}'\) contains only one unique key and A is already sorted, allowing the algorithm to terminate immediately. As \(n\ge m\), \(\lceil n/lg^2n\rceil\ge m/lg^2m\), thus the bit vector is large enough to sort any subsequence of A using the algorithm from Section 2.

**The buffer memory** is then repeatedly created by a partition based loop. At the _i_th iteration, let \(\mathcal{A}'\) be subdivided into two regions _A<sub>S</sub>A<sub>U</sub>_, where all elements in _A<sub>S</sub>_ are in their correct sorted positions, and sorting _A<sub>U</sub>_ would sort \(\mathcal{A}'\). Initially _A<sub>S</sub>_ is empty. At the _i_th iteration, let the size of _A<sub>U</sub>_ be _n<sub>i</sub>_. Using the linear time in-place selection algorithm from [5], we select a pivot _p_ with rank \(\lceil n_i/4\rceil\) and partition _A<sub>U</sub>_ by _p_, resulting in the regions \(A_<pB_\ge\) where _A<sub><o></o></sub>_ contains _n<sub>i,<o></o></sub>_ elements _\<p_ and \(B_\ge\) contains elements \(\ge p\). Then, using \(B_\ge\) as the buffer memory and simulating _V_ with the blocks _L_ and _R_, we sort _A<sub><o></o></sub>_ by the additional memory algorithm from Section 2. Due to the classification of active and buffer elements relative to _p_, distinguishing active from buffer elements can be done by comparing against _p_: active(_x_) simply needs to return the Boolean result of _x\<p_. Because \(|A_<|\le\lceil n_i/4\rceil-1\) and \(|B_\ge|\ge n_i-\lceil n_i/4\rceil\), \(|B_\ge|\ge 3|A_<|-1\), the buffer size is sufficient. Lastly, we isolate all elements =_p_ in \(B_\ge\), resulting in the two blocks _P_ containing elements =_p_ and _B<sub>\></sub>_ holding the remaining elements. In the resulting sequence, the blocks _A<sub><o></o></sub>P_ are already in their correct sorted positions, thus we begin the next iteration with _B<sub>\></sub>=A<sub>U</sub>_. In each iteration, the selection and partitioning steps require _O(n<sub>i</sub>_) comparisons and _O(n<sub>i</sub>_) moves. Eventually, when |_A<sub>U</sub>|\<_2<sup>19</sup>=524288, the entire block _A<sub>U</sub>_ is sorted by table sort from Section 2.7 as a base case, and the algorithm terminates as A is sorted.

\(\blacktriangleright\) **Theorem 3.1.** _The input array_ A_, consisting of n elements, can be sorted in-place using w.e.h.p. n_lg_n+O(n_) _comparisons, always O(n_) _moves, and O(n_lg_n_) _arithmetic operations._

**Proof.** The choice of the pivot _p_ guarantees \(n_{i+1}\le 3/4n_i\), meaning the size of _A<sub>U</sub>_ decays geometrically: \(\sum_{i=1}^In_i=O(n)\), where _I_ is the number of iterations. Furthermore, because _A<sub>U</sub>_ shrinks by more than _n<sub>i,<o></o></sub>_ elements every iteration, \(\sum_{i=1}^In_{i,<}\le n\). Letting \(C'(m)\) and \(M'(m)\) denote the number of comparisons and moves respectively for the additional memory algorithm to sort _m_ elements, we sum for the comparisons _C(n_) and moves _M(n_) to sort A:

\(C(n)=O(n)+\left(\sum_{i=1}^IC'\left(n_{i,<}\right)+O(n_i)\right)\le C'(n)+O(n),M(n)=O(n)+\left(\sum_{i=1}^IM'\left(n_{i,<}\right)+O(n_i)\right)\le M'(n)+O(n)\) (11)

The detailed calculation is in [App. D]. Substituting _m_lg_m+O(m_) comparisons and _O(m_) moves from Theorem 2.6 yields the stated costs. Furthermore, as all arithmetic operations correspond with comparisons and moves, they are bounded by _O(C(n_)+_M(n_))=_O(n_lg_n_).

The w.e.h.p. property is also inherited: the same Chernoff bound in [App. C] holds globally for cumulative failed probes across all iterations. The probability of large deviations (_\>n_ more comparisons than the expected amount) remain bounded by (27/32)_<sup>n</sup>_ [App. D]. \(\blacktriangleleft\)
