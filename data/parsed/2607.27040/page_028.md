**Proof of Remark 2.8.** A key advantage of deterministic cache lines is its stability on active elements. Here we formally prove this property by analyzing the relative order of equal active elements across the two distinct phases of the algorithm: insertion and extraction.

**Insertion.** We prove stability by induction on the sequence of inserted elements from the input array _A_. During initialization, the first \(\lfloor s/2\rfloor\) elements of _A_ are directly swapped in order into _S_<sub>0</sub>, trivially preserving their relative order. For any subsequent element \(x\in A\) processed chronologically, assume by induction that the current global logical sequence \(S_0f'_1S_1G'_1f'_2S_2G'_2\dots f'_{s_\#}S_{s_\#}G'_{s_\#}\) maintains the relative input order of all previously inserted equal active elements. To advance the inductive step, it suffices to establish that after inserting _x_ into the structure: (i) _x_ is placed strictly after all existing equal instances of _x_ in the logical sequence, and (ii) the relative order of all existing equal active elements remains unchanged. We verify both conditions by step-by-step inspection of the insertion procedure:

**1.** The initial search query, _R._search(_x_) locates the active representative \(R'_z\) satisfying \(f'_z\le x<f'_{z+1}\), i.e. the last active representative \(\le x\). Consequently, no previously inserted elements equal to _x_ can exist at or after \(f'_{z+1}\), due to the ordering invariant.

**2.** The element is then inserted into the cache line \(G'_z\). The cache insertion initially appends _x_ to back of the first level. As the first level physically occupies the end of a cache line, this places _x_ after all previous active elements in \(G'_z\). Because no equal active elements exist at or beyond \(f'_{z+1}\), this placement guarantees _x_ is positioned after all existing equal elements within the global sequence. Any subsequent element movement through deterministic cache levels does not change the order of active elements, as each lower level block is placed after all active sub cache blocks in the higher level, meaning the active elements in the moved cache block remains behind all active elements in upper levels, but before all active elements in the lower levels.

**3.** When \(G'_z\) fills and is flushed, its active elements are swapped into the next available buffer spaces of _S<sub>z</sub>_ in descending order of cache level, exactly as cache lines are physically arranged. This process appends the entire contents of \(G'_z\) directly to the back of _S<sub>z</sub>_. As _S<sub>z</sub>_ directly precedes \(G'_z\) in the logical sequence, the order of active elements is unchanged.

**4.** If a flush causes _S<sub>z</sub>_ to reach its maximum capacity, the splitting process explicitly uses stable selection and partitioning procedures to ensure the relative order of equal active elements remains constant. Allocating the new segment, moving the \(\ge a_\mathrm{med}\) block, and creating the new active representative simply redistributes the _s_ active elements originally in _S<sub>z</sub>_ to occupy an expanded contiguous zone \(S_zG'_zf'_{z+1}S_{z+1}\) (as shown in Figure 2) without permuting the elements. To confirm that _a_<sub>med</sub> assumes this exact position as \(f'_{z+1}\), note that _R._insert internally utilizes _R._search to determine the insertion location. Because \(f'_z\le a_\mathrm{med}\le f'_{z+1}\) by the ordering invariant, _R._search is guaranteed to locate \(f'_z\), constructing the new active representative containing _a_<sub>med</sub> directly after \(f'_z\) to take the slot of \(f'_{z+1}\). Any subsequent dynamic rebalancing or resizing operations within _R_ merely collect and redistribute active elements locally within a contiguous interval of gaps, preserving their relative order.

**Extraction.** During extraction, all remaining cache lines \(G'_i\) are flushed into their corresponding segments _S<sub>i</sub>_, which preserves the relative order of active elements as established previously. Each segment _S<sub>i</sub>_ is then locally sorted using the small sort routine, making use of table sort and _k_-way merging, both of which are inherently stable, maintaining the relative order of active elements. Finally, the active elements are swapped back into _A_ in the order \(S'_0f'_1S'_1f'_2\dots f'_{s_\#}S'_{s_\#}\) (all \(G'_i\) contain no active elements and thus are safely omitted). Since the insertion phase maintains global relative order and each segment group is stably processed, this final extracted array retains the exact input order of equal elements.
