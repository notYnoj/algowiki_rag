The algorithm works with binary characters after constant and unsuitable columns have been removed [5]. For a variable binary character, the minimum possible number of state changes is one. In the absence of ambiguous states, pairwise compatibility of binary characters is sufficient for compatibility of the complete set.

Ambiguous bases, represented by N in the input considered here, make the problem more involved. Two characters may admit a pairwise compatible resolution without a single resolution being valid for every character in a larger set. The algorithm therefore resolves ambiguities iteratively and repeats the maximum weight clique calculation as required. Maximum weight clique enumeration is consequently a central combinatorial subproblem of the complete phylogenetic procedure, rather than a complete one-step reduction of every ambiguous instance.

The characters form the vertices of a compatibility graph, with an edge between two characters when they are pairwise compatible under the current resolution. A maximum weight clique represents a maximum weight set of pairwise compatible characters, from which we obtain an optimal character set if we are able to fully resolve all ambiguities. All maximum weight cliques are retained because different optimal character sets lead to different resolved trees. The final output is obtained from the strict consensus of the resulting tree set, which retains only relationships that occur in every tree in that set.

Therefore, the main optimisation problem is to enumerate all maximum weighted clique for an input weighted graph. This is a computationally difficult challenge and even the simpler problem of finding a single maximum clique is well-known to be NP-hard [12]. There are some preprocessing refinements that are made to improve the performance of the algorithm. First, the consolidation of similar characters: consider two compatible characters that share the same pattern of compatibilities among the other characters; if one character is in the maximum clique, the other must be too. Therefore, Cherry combines these characters into a single vertex with a weight representing the number of characters that vertex represents. As a result, the optimisation problem we wish solve then becomes a slight variant of the maximum clique problem: the _Maximum Weighted Clique (MWC) Enumeration Problem_. Second, the algorithm further reduces the size of the input to the MWC problem in a variety of ways. All such reductions are made to determine the vertices for which their inclusion in an MWC can be determined with certainty.

## 2.1.2 Preprocessing

Let us first describe the preprocessing performed in [5] in more detail, as this is a crucial part of the algorithm that has dramatic effects on the graph size, enabling very large instances to be manageable by the algorithm. It prunes vertices of the graph for which we can determine their inclusion in _all_ MWCs with certainty. If it can never be in any MWC, we can simply ignore it; and if it is in every MWC, we can simply store it separately and add it back at the end. As the main MWC enumeration portion of the algorithm is clearly the most inefficient part, any reduction in graph size prior to entering said subroutine provides worthwhile improvements.
