## 3.1 Quantum ordinal optimization

**Definition 1** (Quantum ordinal optimization)**.** A quantum ordinal optimization problem specifies a class of unknown configurations, each of which determines a strict order of _n_ designs and may contain further data such as performance values or gaps. It specifies the good-enough set of the _r_ best designs, an oracle whose responses depend on the configuration, a budget of at most _q_ calls on every branch of an algorithm’s measurements and private randomness, and the size of the selected set and its alignment level. The oracle model specifies its quantum action and the response to a classical query. An algorithm succeeds when its output set contains at least the prescribed alignment level of good-enough designs.

An admissible quantum algorithm uses input-independent state preparation, unitary operations, measurements, private randomness and finite workspace. It has no postselection and no access to the configuration except through the specified oracle. The classical counterpart uses private randomness and adaptive queries to the same oracle on one classical input at a time. Both obey the prescribed query budget and selected-set size. The quantum value is the supremum, over admissible quantum algorithms, of the infimum of their success probabilities over the configuration class. The classical value is defined in the same way over classical algorithms.

The oracle can provide comparisons, evaluations or membership information, and the selected set can contain one or several designs. Each choice specifies a QOO problem with its own classical benchmark. For a fixed oracle and selected-set size, the quantum value of a QOO problem is the optimal success probability of a query problem at a fixed number of queries, the quantity studied for other problems in the few-query work of Section 2. What OO adds is the good-enough target with its alignment level, the size of the selected set, and the comparison with the optimal classical procedure and with blind pick. Section 8.2 discusses how changes in evaluation and selection affect the formulation.

## 3.2 The exact-comparison instance

We study the instance of Definition 1 whose configurations are all strict orders, with the exact comparison oracle, selected-set size one and alignment level one. Classical and quantum procedures use the same comparison rule and good-enough target. They differ in how they query that rule, and this instance requires neither performance values nor numerical gaps between designs.

Let [_n_]={1_,...,n_} label _n_ designs. Their unknown performance order is a strict order, encoded by the rank vector _x_=(_x_<sub>1</sub>_,...,x<sub>n</sub>_), a permutation of [_n_] in which rank 1 is best. An algorithm receives labels and oracle answers, never ranks. For \(0\le r\le n\) the good-enough set is the true top _r_, \(G_r(x)=\{i:x_i\le r\}\). The algorithm outputs one label _I_, and it succeeds when \(I\in G_r(x)\). In OO terms the selected set is {_I_}, of size one, the alignment level is one, and the alignment probability is \(Pr[x_I\le r]\) [3]. For _r_=1, this is the probability of correct selection (PCS) in ranking and selection [32]. For _r\>_1, it is a rank-based form of the probability of good selection (PGS), where goodness requires rank at most _r_, whereas Eckman and Henderson define good selection by a mean performance gap from the best that is smaller than a prescribed tolerance [33].
