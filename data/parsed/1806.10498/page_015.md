## 8 Appendix

### 8.1 Alphabetic s

Our solution of the dynamic alphabetic tree problem can be also used to maintain a dynamic alphabetic code with almost-optimal length. There is a one-to-one correspondence between binary prefix-free codes and binary trees. Given a tree _T_, every root-to-node path in _T_ can be encoded by a codeword: we write a 0-bit for every edge from a node to its left child and a 1-bit for every edge from a node to its right child. Using this correspondence we can translate our alphabetic tree method into an adaptive alphabetic encoding. However this method would produce an alphabetic encoding in _O_(log_n_) time per symbol in the worst-case or in _O_(1) time on average: to generate a codeword we would need to traverse a path from the root to a leaf. In this section we show that an even better result is possible: we can encode a sequence of symbols in _O_(1) time per symbol. To achieve this goal, some changes in the core method of maintaining the tree _T_<sup>S</sup> are necessary. In our new method, described in Lemma 8 we move only the leaves of _T_<sup>S</sup>. This modification allows us to store explicitly the codewords all symbols. We will use the following notation in this section: _w<sub>i</sub>(t_) will denote the number of times the symbol _a<sub>i</sub>_ occurs in the length-_t_ prefix of a sequence _S_ and we will denote by _S[t_] the _t_-th symbol in _S_.

**Lemma 8** _There is a binary alphabetic code such that the codeword length of the symbol S_\[_t_+1\]=_a<sub>i</sub> does not exceed_ min(log(_t/w<sub>i</sub>(t_)),log_n_)+_O_(1)_. The cost of updating the code after encoding a symbol or inserting a new symbol into_ C _is O_(log<sup>3</sup>_n)._

_Proof:_ We maintain a tree _T_<sup>S</sup> of pseudo-leaves, as in the case of alphabetic trees. However, we use a different method to maintain the tree: we only move the leaf nodes in the tree; internal nodes are never moved. There are \(4W'\) pseudo-leaves in our modified tree and all pseudo-leaves are stored in an array _B_. Some pseudo-leaves are associated to symbols; we associate \(2w'_i(t)\) pseudo-leaves to the symbol _a<sub>i</sub>_, where \(w'_i(t)=w_i(t)/\tau\) and \(\tau=t/n\). The non-associated pseudo-leaves are called dummy pseudo-leaves. For any _i_, pseudo-leaves for the symbol _a<sub>i</sub>_ precede the pseudo-leaves for the symbol _a_<sub>_i_+1</sub>. When a new pseudo-leaf is inserted, positions of some other pseudo-leaves in _B_ may change; that is, some pseudo-leaves are shifted to the right (or to the left) in _B_, but their relative order remains unchanged. We can maintain elements in _B_ in such a way that at most log<sup>2</sup>_n_ pseudo-leaves are moved to different positions in _B_ after every insertion \[9,27\]. For every _a<sub>i</sub>_, there is a node \(\varepsilon_i\) such that all pseudo-leaves below \(\varepsilon_i\) are associated to _a<sub>i</sub>_. The height of \(\varepsilon_i\) in _T_<sup>S</sup> is \(\mathrm{log}(w'_i(t)\). The depth of \(\varepsilon_i\) in _T_<sup>S</sup> is at most min(log(_t/w<sub>i</sub>(t_)),log_n_)+_O_(1). When a new element is inserted or when \(w'_i(t)\) is changed, we need to insert a new pseudo-leaf and move _O_(log<sup>2</sup>_n_) other pseudo-leaves. After every move, we may have to update some node \(\varepsilon_i\); in this case we also recompute the codeword for the symbol _a<sub>i</sub>_. For every moved pseudo-leaf, we identify its ancestor \(\varepsilon_i\); if necessary, we change the position of \(\varepsilon_i\) in _T_<sup>S</sup> and update the codeword for _a<sub>i</sub>_ in _O_(log_n_) time. Since we move _O_(log<sup>2</sup>_n_) leaves, we might change codewords for _O_(log<sup>2</sup>_n_) symbols. The total time needed to insert a new pseudo-leaf is _O_(log<sup>3</sup>_n_).

Thus our dynamic search trees produce a dynamic alphabetic code that can be updated in _O_(1) time and encodes the sequence of _W_ symbols in _W(H+O_(1)) bits, where _H_ denotes the entropy of _W_. We can reduce the time to maintain the code with the same technique as in the case of binary trees.
